# HDR の環境 (空と環境光)

正距円筒の HDR 画像 (Radiance の `.hdr`) を、空と PBR の環境光 (IBL) にします。明るさは 1 を超えたまま持つので、太陽は金属や水の反射にも明るいまま映ります。既定は使わず、使わなければ今までと同じ絵です。DX12 だけで効き、Dawn は今の環境のままです。

## 使い方

`draw` で毎フレーム呼んでかまいません。同じ指定なら何もしません。

```cpp
s.environmentHdr3D("assets/sky/day_field_2k.hdr", 1.0f, Deg{0.0f});   // 画像、明るさ、向き
s.environmentHdr3D("");                                                // 外す。入れる前の environment3D / skybox3D に戻る
```

- 画像の path は assets からの相対 (DLL の隣を先に探す) か絶対です。読めないときは 1 度だけ知らせて、環境は今のままです。
- PBR で受けるには `SceneLook::shadingModel = 3` にします。トゥーンの陰影には環境光が効きません。
- 入れている間に `skybox3D` や `environment3D` を呼ぶと、その色は預かるだけで、外したときに戻ります。HDR のほうが先に立ちます。
- 環境光が当たるのは、forward で描く物 (`drawMesh`、スキンの人形、回転を `Vec3` で渡す `drawModel`) です。`.clod` と、回転を `Deg` で渡す `drawModel` (clod の経路) には当たりません (見本で、金属の球が黒いままになることを確かめました)。見本の glb は `drawModel(path, pos, Vec3{0, 0, 0}, 1.0f)` で描いています。
- 見本は `examples/hdr_sky` です。

| 引数 | 効き方 | 変えたときの費用 |
|---|---|---|
| `intensity` | 空の色と環境光に掛けます (1 で画像のまま) | なし。読み直しも畳み込みもしません。毎フレーム変えてよい |
| `yaw` | 画像を Y 軸のまわりに回します。正で、u = 0.5 の向きが -Z から +X の側へ回ります | cubemap と畳み込みを作り直します (下) |
| 画像の name | 読み直します | 読み込みと畳み込み |

## 画像

読める形は、Radiance の RGBE (`FORMAT=32-bit_rle_rgbe`) の無圧縮、新形式の RLE、旧形式の RLE です。向きは `-Y h +X w` (上から下) と `+Y h +X w` (下から上) で、読んだ結果は常に行 0 が上です。XYZE (`FORMAT=32-bit_rle_xyze`) とそれ以外の向きは断ります。`FORMAT=` の行が無い古いファイルは、Radiance の既定 (RGBE) とみなして読みます。`EXPOSURE=` の行は stb_image などと同じく掛けません。1 辺 16384、6700 万画素までです。EXR は読みません。

画像の約束は次のとおりです。

- 行 0 が天頂、行の真ん中が地平
- u = 0.5 が -Z、u が増えると上から見て +X の側へ回る

素材は著作権に気をつけて選びます。見本の `day_field_2k.hdr` は式から描いた物です (青空、もや、地面、雲、太陽の円盤。太陽は -Z から +X の側へ 40 度、高さ 38 度、明るさ 4000)。

## 空と環境光の作り方

画像を 1 つの float の cubemap (`render/HdrCubemap.hpp`) にして、空と環境光で使い回します。

| 用途 | 形式と大きさ | 作り方 |
|---|---|---|
| 空 | RGBA16F。1 面は画像の幅の 1/4 を 256 から 1024 に収める (2k の画像で 512、4k 以上で 1024) | 画像を双線形で引く |
| 拡散の環境光 (irradiance) | RGBA16F、32 の面 | 元の cubemap を一辺 16 に畳み、全テクセルを立体角つきで総当たりに積分する。標本の揺れが無く、太陽があってもまだらにならない |
| 鏡面の環境光 (prefilter) | RGBA16F、128 から半分ずつ 5 段 (粗さ 0、0.25、0.5、0.75、1) | GGX の重点標本 128 個。標本の立体角から元の mip を選ぶので、太陽のような小さく強い光でも点々にならない。粗さ 0 は元の写し |
| 環境 BRDF の表 | R32G32F、64 x 64 | 今までと同じ (環境に依らない) |

float の元は GPU へ写すまでの間だけ持ちます。写したあとは手放します (読んだ画像は、向きだけ変えるときに読み直さないよう、HDR の間だけ残します)。

太陽の円盤の明るさが 65504 (half の上限) を超える画像は、上限で止めます。無限大にはしません。

## 太陽は二重に数えない

画像の中の太陽は、環境光 (拡散と鏡面) にもう入っています。`light3D` の直射を足すと、拡散は 2 回数えます。直射は影を落とすために足す物として、`light3D` の色は弱めにします。画像の太陽の向きを `light3D` と `shadowDirection` に渡すと、空と影がずれません (見本は画像の太陽の向きを書いてあります)。

## 費用

| | 大きさ |
|---|---|
| 空 (2k の画像) | 約 12.6 MiB (6 面 RGBA16F) とアップロード用の同じ大きさ。4k 以上の画像は 1024 の面で約 50 MiB ずつ |
| 環境光 | 約 1.1 MiB |
| CPU (読み込みと畳み込みの間) | float の元 約 19 MiB (512 の面)、1024 の面で約 75 MiB。読んだ画像 (2k で約 25 MiB) は HDR の間残る |
| 最初の呼び出し (2k の画像、この開発機での測定) | 最適化あり 約 0.2 秒、Debug ビルド 約 0.6 秒。ロード中に呼ぶ。yaw を変えると cubemap と畳み込みを作り直すので約 0.15 秒 (最適化あり) かかり、毎フレーム回すのには向かない |

使わないフレームは、パスも資源も増えません。使うと、空は今までの skybox と同じ 1 回の描画で、環境光は PBR の陰影が今まで読んでいた表を、RGBA16F に替えて読むだけです。

## 録画とリプレイ

画像の name、intensity、yaw はゲームの `draw` が頼む値なので、台本が同じなら同じ指定になります。畳み込みは CPU の float で、各面を別のスレッドが書きますが、面どうしは影響しないので結果は毎回同じです。同じ台本は同じ画素になります。

## Dawn

描きません。Dawn には PBR の陰影と環境の cubemap が無いので、機能表の `hdr_environment` は Dawn を「なし」とし、頼まれた回数を `--render-features` の知らせに数えます。1 度だけ警告を出して、環境は今のままです。Dawn の空は `sky_atmosphere` の別手法のままです。

## 実機で見る手順

`mitiru_host.exe hdr_sky/hdr_sky.dll` を起動します。水面に空の雲と太陽の筋が映り、球は粗さの順に反射がぼけます。Space で色の空に切り替えて見比べます。HDR 出力 ([HDR_OUTPUT.md](HDR_OUTPUT.md)) のモニターでの見た目は、この開発機が SDR なので測れていません。空の明るい所 (太陽) は、HDR 出力では SDR より白く伸びるはずですが、実機では未確認です。
