画面を作る

HUD とメニューは、HTML / CSS で

ゲームのルールは C++、画面（スコア表示・メニュー・ダイアログ）は HTML と CSS で書きます。C++ が名前付きの値を送り、HTML 側は data-m-* 属性で受け取るだけなので、つなぎ役の JavaScript を書く必要はありません。あとはエンジン同梱の binder が、画面を自動で同期します。

仕組み

値が流れる向きは一方通行

状態を持つのは C++ だけ。C++ → 画面は「値を送る」、画面 → C++ は「操作を伝える」。この 2 方向しかありません。ゲームの状態を HTML 側に持たせないので、表示がズレません。

C++ → 値を送る → HTML が表示

どのファイル？ 画面（HUD・メニュー）は assets/scene.html に書きます。これが HTML のエントリポイントで、エンジンがゲーム画面の上に重ねます。CSS はその <style> の中（別ファイルにしてもOK）。C++ 側の hud.set(...) は update(Input in, Hud hud, float dt) の中に書きます（送るには引数の Hud hud が要ります）。完成形のファイル全体は 下の完成例を見てください。

まず scene.html の末尾で、エンジン付属の部品を 2 つ読み込みます。mitiru build が mitiru_runtime/ をシーンの隣へ自動コピーするので、書くのはこの 2 行だけです。

html
<script src="mitiru_runtime/mitiru_cef_state.js"></script>  <!-- 受け渡し -->
<script src="mitiru_runtime/mitiru_bind.js"></script>       <!-- 同期役 -->

値を表示する

C++ の値を、画面に出す

C++ で hud.set("view.…", 値) と送った値を、HTML 側で同じ名前を指して受け取ります。

data-m-* は HTML 標準の「data 属性」を使った目印で、「この要素に、この名前の値を結びつけて」という意味です。たとえば data-m-text="view.hud.score" なら、「この要素の中身（テキスト）に、view.hud.score の値を入れて」という指示になります。

C++

値を送る

cpp
hud.set("view.hud.score", score);   // 数値
hud.set("view.hud.combo", combo);
hud.set("view.boss.active", true);  // 真偽
HTML

受け取る

html
<!-- textContent に値を入れる -->
<div class="hud">SCORE <span data-m-text="view.hud.score">0</span></div>

<!-- 文に埋め込む（テンプレート） -->
<p data-m-tpl="コンボ {view.hud.combo} 連鎖！"></p>

<!-- 値が真のときだけ表示 -->
<div class="boss-bar" data-m-show="view.boss.active">…</div>

data-m-text の初期値（上の 0）は、まだ値が来ていないときに見えるフォールバックです。書いておくと、画面が一瞬空っぽになりません。

上の 3 つは、画面ではこう出ます:

SCORE 1240 コンボ 7 連鎖！ BOSS

主な属性

よく使う data-m-*

data-m-* は「HTML のこの場所と、C++ のこの値を結びつけて」という印です。よく使うものを 1 つずつ、C++ で送るコード → HTML での書き方 → 画面に出るものの順で見ていきます。まずは data-m-text だけ覚えれば十分です。

data-m-text — 値をそのまま出す

いちばん基本。指した値を、その要素の中身（テキスト）として表示します。

C++ — 値を送る
hud.set("view.hud.score", 1240);
HTML — 受け取る
SCORE <span data-m-text="view.hud.score">0</span>

画面 → SCORE 1240（中の 0 は、値が来る前に見えるフォールバック）

SCORE 1240

data-m-format — 数字を読みやすく整える

data-m-text に添えると、桁区切りや時間表示に整形できます。

HTML
<span data-m-text="view.gold" data-m-format="comma">0</span>

hud.set("view.gold", 1234567) → 画面 1,234,567。ほかに kmb（→ 1.2M）・pct（→ 62%）・time（秒を → 01:23）・int（小数を整数に）。

comma → 1,234,567 kmb → 1.2M time → 01:23

data-m-tpl — 文の中に値を埋める

複数の値を 1 つの文に差し込みたいとき。{名前} の所が値に置き換わります。

C++
hud.set("view.hp", 80);
hud.set("view.max", 100);
HTML
<p data-m-tpl="HP {view.hp} / {view.max}"></p>

画面 → HP 80 / 100

HP 80 / 100

data-m-show / data-m-hide — 出したり隠したり

値が真（true や 0 以外）のときだけ表示。条件式も書けます。data-m-hide は真のとき隠す逆版。

C++
hud.set("view.boss.active", true);
hud.set("view.hp", 0);
HTML
<div data-m-show="view.boss.active">ボス出現！</div>
<div data-m-show="view.hp <= 0">GAME OVER</div>   <!-- == != < > <= >= が使える -->

画面 → 「ボス出現！」が出る。hp が 0 以下になった瞬間「GAME OVER」が出る。

ボス出現！ hp が 0 になると ↓ GAME OVER

data-m-class — 条件でクラスを付ける（色・アニメ）

「クラス名: 条件」と書くと、条件が真のときだけそのクラスが付きます。見た目の変化は CSS 側で。

HTML + CSS
<div class="hpbar" data-m-class="danger: view.hp <= 20">…</div>

<style>
  .hpbar.danger { color: red; animation: blink 1s infinite; }  /* danger が付くと赤点滅 */
</style>

画面 → hp が 20 以下になると danger クラスが付いて、バーが赤く点滅。

hp 15（危険）:

data-m-style — 値を CSS の数値に流す（ゲージ）

体力バーなど「値に応じて幅や高さを変える」もの。{名前} の所に値が入ります。

HTML
<div class="bar">
  <div class="fill" data-m-style="width: {view.hp.pct}%"></div>
</div>

hud.set("view.hp.pct", 62) → 中の fill の幅が 62% に。値が変われば伸び縮みします。

62%:

data-m-attr — 任意の属性に流す（画像差し替えなど）

テキストではなく、src や title などの属性に値を入れたいとき。

HTML
<img data-m-attr="src: {view.face}">

hud.set("view.face", "happy.png") → 画像が happy.png に切り替わる。表情差分などに。

😊 "angry.png" を送ると → 😣

data-m-flash / data-m-tween — 変化を演出する

値が変わったときに見せ方を足すもの。flash は一瞬光らせ、tween は数字をなめらかに動かします。

HTML + CSS
<!-- スコアが変わるたび m-flash クラスが一瞬付く（取得演出）-->
<span data-m-text="view.score" data-m-flash="view.score">0</span>
<style> .m-flash { animation: pop .3s; } </style>

<!-- 0 → 新しい値へ ~0.3 秒でカウントアップ -->
<span data-m-text="view.score" data-m-tween="view.score">0</span>

画面 → 値が変わるたびに、ぴくっと光ったり、数字がパラパラ動いたりします。

スコア取得の瞬間: 1,240

ボタンの click を C++ に伝える data-m-action と、リストを並べる data-m-repeat は、それぞれ 下の「操作を伝える」・「リストを並べる」で扱います。

操作を伝える

ボタンの click を、C++ へ

画面 → C++ は「操作の通知」だけ。ボタンに data-m-action を付けると、押された合図が C++ に届きます。中の処理（ゲームのルール）は C++ が決めます。

html
<button data-m-action="start">はじめる</button>
<button data-m-action="select" data-m-arg="'hard'">むずかしい</button>

data-m-arg は引用符付き（'hard'）なら文字列、数値（42）ならそのままの値、それ以外は状態のパスとして解決されて C++ に届きます。スライダーやドロップダウン（input / select）に data-m-action を付けると、現在値が合図と一緒に渡ります。設定画面の音量調整などに使えます。

くり返し

リストを並べる

手札・インベントリ・ランキングのような可変リストは、data-m-repeat と <template> で。要素は使い回されるので、毎フレーム更新しても重くなりません。

html
<div class="hand" data-m-repeat="view.hand">
  <template>
    <div class="card" data-m-action="play" data-m-arg="i">
      <span data-m-text="cost"></span>
      <span data-m-text="name"></span>
    </div>
  </template>
</div>

リストの中では、項目のフィールドを view.… を付けずに そのまま（data-m-text="name"）指します。C++ 側は StateWriter の array() / list() で送ります。

完成例

これがまるごと 1 枚の HUD

スコア表示と、勝敗のモーダルを 1 つにした assets/scene.html です。手書きの JavaScript は 1 行もありません ── C++ が view.hud.* を送り、data-m-* が表示するだけ。見た目は普通の CSS です。

下の scene.html を書くと、ゲーム画面の上にこんな HUD が乗ります:

SCORE 1240
CLEAR!
もう一度
html — assets/scene.html
<!doctype html>
<html lang="ja">
<head>
  <meta charset="utf-8">
  <style>
    body { margin: 0; font-family: sans-serif; color: #fff; }
    .hud { position: absolute; top: 16px; left: 20px; font-size: 28px; }
    /* 勝敗モーダル。is-on が付いたときだけ出す */
    .modal { position: absolute; inset: 0; display: none;
             align-items: center; justify-content: center;
             background: rgba(0,0,0,.6); }
    .modal.is-on { display: flex; }
    .card { background: #1b2030; padding: 32px 48px; border-radius: 12px; text-align: center; }
    button { margin-top: 16px; padding: 10px 24px; cursor: pointer; }
  </style>
</head>
<body>
  <!-- スコア（C++ の hud.set("view.hud.score", …) が反映される）-->
  <div class="hud">SCORE <span data-m-text="view.hud.score">0</span></div>

  <!-- over が真のとき is-on が付いて表示。outcome で文言を出し分け -->
  <div class="modal" data-m-class="is-on: view.hud.over">
    <div class="card">
      <h1 data-m-show="view.hud.outcome == win">CLEAR!</h1>
      <h1 data-m-show="view.hud.outcome == lose">GAME OVER</h1>
      <button data-m-action="restart">もう一度</button>
    </div>
  </div>

  <!-- エンジン付属の 2 つ。mitiru build が隣に自動コピーする -->
  <script src="mitiru_runtime/mitiru_cef_state.js"></script>
  <script src="mitiru_runtime/mitiru_bind.js"></script>
</body>
</html>

C++ 側はこれを送るだけ:

cpp
hud.set("view.hud.score", score);
hud.set("view.hud.over", over);
hud.set("view.hud.outcome", won ? "win" : "lose");
if (in.action("restart")) reset();   // ボタンの click はここで受ける

CSS は普通の Web と同じです。影・角丸・グラデ・@keyframes アニメ・backdrop-filter のぼかしまで、そのまま使えます（中身は本物のブラウザエンジン）。スコアの数字を data-m-tween でカウントアップさせたり、モーダルの登場を CSS アニメにしたり ── 見た目はすべて HTML/CSS 側で完結します。

つまずきやすい点

出ないときは、名前を疑う

C++ が一度も送っていない名前を data-m-* で指すと、エラーは出ず、HTML に書いた初期値がそのまま残ります。「値が変わらない」ときは、まず C++ の set とスペルが一致しているか確認してください。

  • C++ の "view.hud.score" と HTML の data-m-text="view.hud.score" は 完全一致が必要です。
  • 見た目（色・余白・アニメ）は CSS の領分。値が来ているのに見えないときは CSS を疑います。

スペル違いを機械的に見つける方法も 2 つあります。コミット前に mitiru lint を回すと、HTML の data-m-* キーが C++ の set したキーと食い違っていないかを照合してくれます。実行中に確かめたいときは <body data-m-debug> を付けるか、シーンを ?mdebug=1 で開くと、未知のキーがコンソールに出ます。

JavaScript を書いてもいい。 data-m-* だけで HUD は組めますが、凝った演出を自分で作りたくなれば JavaScript も書けます（中身は本物のブラウザエンジンです）。まずは書かずに作り、必要になったら手を伸ばせます。

まずは 初心者ガイド（C++ だけのドッジゲーム）で土台を作ってから、HUD を HTML に置き換えていくのがおすすめです。
