02 画面に UI を出す

C++ で動いているゲームの上に、HTML/CSS で作った HUD を重ねる。ロジックは C++、UI は HTML/CSS、つなぎは StateWriter + data-m-* の宣言バインダ。手書き JS はゼロ。

このページで分かること

  • mitiru new の雛形には最初から透過 HUD が付いている。その仕組みを読み解く
  • C++ は on_update で StateWriter に名前付きの値を push するだけ
  • HTML は data-m-* 属性で値を映すだけ。手書き JavaScript は書かない

01 で動かした C++ ゲームの上に、HTML/CSS の 見た目だけのレイヤー を重ねます。HUD バー、ダイアログ、メニューなど、Web のデザイン資産を活かしたい部分はここに乗ります。

実は mitiru new の雛形には最初から透過 HUD が付いています。このチュートリアルでは、その仕組み（C++ の StateWriter と HTML の data-m-*）を読み解き、HUD に「経過時間」を足します。手書きの JavaScript は 1 行も書きません。

時間の目安は 15 〜 20 分。先に 01 を済ませてください。

できあがるもの

  • 暗い背景の上を動く水色の矩形プレイヤー（01 と同じ、C++ 描画）
  • 画面左上の半透明 HUD バー（HTML/CSS）
  • HUD に座標と「経過時間」が出て、毎フレーム C++ から更新される

役割分担をはっきりさせる

やること どこに書く
経過時間を数える / 座標を持つ C++（on_update、状態は GameMemory）
プレイヤーや背景の描画 C++（on_draw）
HUD のレイアウトと見た目 HTML / CSS
HUD に値を映す data-m-* 属性（宣言バインダが自動でやる）
「次に何が起きるか」を決める C++。HTML/JS では決めない

ゲームのロジックを HTML/JS 側に書かない、これが一番大事です。C++ が名前付きの値を push し、HTML はその値を data-m-* で映すだけ。間をつなぐ JavaScript はエンジン同梱のバインダ（mitiru_bind.js）が担うので、あなたは JS を書きません。

設計メモ — なぜ役割を分けるのか

「全部 C++ で描けばいいのでは?」とも思えますが、グラデーション・半透明・組版・アニメーションは HTML/CSS のほうが圧倒的に作りやすい。一方で ゲームのルールまで HTML 側に持つと、状態が C++ と HTML に二重化して必ずズレます。だから「真実は C++ にだけ置き、HTML はそれを映すだけ」と決めます。値の受け渡しを宣言的な data-m-* に寄せると、その規律が構造的に守られます（手書き JS で状態を持てない）。

手順 1: 雛形を作って走らせる

mitiru new my-ui
cd my-ui
mitiru watch

矢印キーで矩形が動き、左上の HUD に座標が出ます。この HUD はすでに動いています ── 次の手順でその中身を読みます。 （mitiru watch なら、以降の編集は保存した瞬間に反映されます。）

手順 2: HTML 側を読む — data-m-* だけで値が映る

雛形の assets/scene.html の本体はこれだけです。

<body>
  <!-- data-m-tpl は {名前} を push された値に差し替える。data-m-show は真偽で表示を切り替える。 -->
  <div class="hud">
    <div data-m-tpl="位置  X {view.x}   Y {view.y}">位置  X 640   Y 360</div>
    <div class="moving" data-m-show="view.moving">— 移動中 —</div>
  </div>

  <!-- バインダ本体。mitiru build が mitiru_runtime/* を隣にコピーする（編集も commit も不要）。 -->
  <script src="mitiru_runtime/mitiru_cef_state.js"></script>
  <script src="mitiru_runtime/mitiru_bind.js"></script>
</body>

ポイント:

  • data-m-tpl="... {view.x} ..." … {view.x} が C++ から push された値に差し替わります。
  • data-m-show="view.moving" … その値が真のあいだだけ要素を表示します。
  • <script> は エンジン同梱のバインダ 2 本だけ。あなたが書く <script> はありません。

CSS で html, body { background: transparent; pointer-events: none; } にしているので、HUD の下に C++ の描画が透けて見え、クリックはゲームへ抜けます。

手順 3: C++ 側を読む — StateWriter で名前付きの値を push

雛形の on_update の末尾で、HUD に映る値を push しています。

#include <mitiru/bridge/StateWriter.hpp>   // ファイル先頭の include に入っている

// on_update の中（移動処理のあと）:
mitiru::bridge::StateWriter w(intents);
w.set("view.x", static_cast<int>(mem.playerX));
w.set("view.y", static_cast<int>(mem.playerY));
w.set("view.moving", left || right || up || down);

StateWriter は FrameIntents（host へのお願いを書く器）に値を積むだけのもの。host がそれを CEF 側へ流し、data-m-* バインダが DOM を更新します。C++ は HTML の <span> も CSS も知りません。名前（view.x など）でだけ繋がっています ── これが signal-only bridge です。

手順 4: HUD に「経過時間」を足す

仕上げに時計を足します。まず GameMemory に経過秒を持たせ、on_update で MM:SS に整形して push します。

struct GameMemory
{
    float playerX = 640.0f, playerY = 360.0f;
    float elapsed = 0.0f;          // ★ 追加
};

// on_update の中:
mem.elapsed += dt;
const int total = static_cast<int>(mem.elapsed);
char buf[8];
std::snprintf(buf, sizeof(buf), "%02d:%02d", total / 60, total % 60);   // <cstdio>

mitiru::bridge::StateWriter w(intents);
w.set("view.x", static_cast<int>(mem.playerX));
w.set("view.y", static_cast<int>(mem.playerY));
w.set("view.moving", left || right || up || down);
w.set("view.time", buf);          // ★ 追加（文字列）

次に assets/scene.html の HUD に 1 行足すだけ。

<div class="hud">
  <div data-m-tpl="TIME  {view.time}">TIME  00:00</div>   <!-- ★ 追加 -->
  <div data-m-tpl="位置  X {view.x}   Y {view.y}">位置  X 640   Y 360</div>
  <div class="moving" data-m-show="view.moving">— 移動中 —</div>
</div>

保存すると（mitiru watch 中なら即時）、HUD の時計が毎秒進みます。

C++ メモ — snprintf と文字列の push

std::snprintf(buf, n, "%02d:%02d", m, s) は %02d が「2 桁・ゼロ埋め」の整数差し込み。<cstdio> が要ります。w.set("view.time", buf) は const char* を受ける overload で、そのまま文字列として push されます。

何が分かったか

  • 見た目の凝った部分は HTML / CSS。グラデーションも backdrop-filter も Web の道具がそのまま使えます。
  • 値の本体は C++。GameMemory に持ち、StateWriter で名前付きに push するだけ。
  • C++ と HTML は state 名 1 個（view.time など）で繋がります。手書き JavaScript は書きません ── つなぎは data-m-* バインダが担います。

やってはいけないパターン

  • HTML/JS 側で状態を持つ / 進める（setInterval で自前の時計を回す等）── 状態が二重化して必ずズレます。時計は C++ 側だけ。
  • HTML/JS に当たり判定やゲームのルールを書く ── HTML/CSS は画面の構造とデザインの道具で、ルールの記述場所ではありません。混ぜると「見た目を直したいだけ」で挙動が壊れます。ルールは C++ 側だけ。

次の一歩

  • 値を増やす: view.score や view.hp も同じく w.set(...) + data-m-tpl で足せます。
  • 条件表示: data-m-show="view.gameover" で勝敗モーダルを出し分ける（実例は examples/breakout の scene.html）。
  • HTML から C++ へ通知: ボタンに data-m-action="game.restart" を付け、C++ 側で input->actionEvents を見れば、UI クリックから C++ のロジックを動かせます。これも signal-only — HTML は「何が起きたか」しか伝えません。
