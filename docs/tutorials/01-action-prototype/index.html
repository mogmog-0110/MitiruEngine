01 2D アクションのプロトタイプ

矩形プレイヤーを矢印キー / WASD で動かす。壁との当たり判定と、画面上の目標 (拾うと得点) を入れる。アクション、シューティング、パズルの基礎になる入力 + 描画の最小ループ。

このページで分かること

  • 矩形プレイヤーを矢印キー / WASD で動かす
  • 壁との当たり判定の最小コード
  • 拾うアイテムとカウンタの仕組み

このチュートリアルでは、こんなものを動かすところまで行きます。

  • 黒い背景の上に動く矩形プレイヤー (約 32 × 32 px)
  • 矢印キー か WASD で 4 方向に移動
  • 画面の端を超えない (壁との当たり判定)
  • 小さい目標 (黄色い円) を 1 個出して、触れたら得点 +1 + 別の場所に再配置
  • 左上にスコア表示

時間の目安は 20 〜 30 分。

キーボードで何かを動かす + 当たり判定 + スコア — あらゆる 2D ゲームに出てくる最小ループです。シューティングなら弾、パズルなら駒、RPG ならフィールドキャラ、見せ方が違うだけで型は同じです。

事前に はじめに を済ませ、mitiru doctor が OK を返すことを確認してください。

全体の構成

やること どこに書く
ウィンドウと CEF の起動 C++
キー入力の宣言 (action map) JS (mitiru.input ランタイム)
プレイヤー / 目標の状態 + 衝突判定 JS
画面の描画 JS + <canvas>

このチュートリアルでは gameplay を JS 側で書きます。MitiruEngine は本来 gameplay を C++ に置く方針ですが、最初のプロトタイプを 1 ファイルで作る段階では JS + canvas が手っ取り早い。breakout / shoot_em_up サンプルも同じ流儀です。本格的に作り込むときは状態を C++ に引き上げてください。

手順 1: プロジェクトを作る

mitiru new my-action
cd my-action

手順 2: C++ 側 (ホスト) を書く

src/main.cpp を開いて、ウィンドウを開いて HTML を読むだけのホストに書き換えます。

#include <mitiru/Mitiru.hpp>

class ActionGame final : public mitiru::Game {
public:
  mitiru::Size layout(int w, int h) override { return {w, h}; }
  void update(float) override {}                  // gameplay は JS 側
  void draw(mitiru::Screen&) override {}          // 描画も JS 側
};

int main() {
  mitiru::Engine engine;
  ActionGame game;

  mitiru::EngineConfig cfg;
  cfg.title = "My Action";
  cfg.windowWidth = 960;
  cfg.windowHeight = 540;
  cfg.cefStartUrl = "file:///" __FILE__ "/../scene.html";

  engine.run(game, cfg);
}

手順 3: HTML と CSS で土台を用意する

assets/scene.html を開いて以下の内容に書き換えます。

<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="utf-8">
  <link rel="stylesheet" href="scene.css">
</head>
<body>
  <canvas id="stage" width="960" height="540"></canvas>
  <div id="hud">Score: <span id="score">0</span></div>

  <script src="mitiru_runtime/mitiru_input.js"></script>
  <script src="scene.js"></script>
</body>
</html>

assets/scene.css を同じ階層に新規作成します。

html, body { margin: 0; height: 100%; background: #0b0e15; overflow: hidden;
             font-family: "Noto Sans JP", sans-serif; color: #fff; }
#stage     { display: block; margin: 0 auto; background: #131826; }
#hud       { position: fixed; top: 12px; left: 16px;
             font-size: 18px; letter-spacing: 0.05em; }

mitiru_runtime/mitiru_input.js は engine 側が同梱する入力ランタイムです。mitiru build が自動で assets/ 隣にコピーするので、パスを変更する必要はありません。

手順 4: 入力 + ゲームループを書く

assets/scene.js を新規作成します。

// --- アクションマップ -----------------------------------------------------
// 矢印キーと WASD を同じ「方向」アクションにまとめる。
mitiru.input.setActionMap({
  up:    ['ArrowUp',    'w', 'W'],
  down:  ['ArrowDown',  's', 'S'],
  left:  ['ArrowLeft',  'a', 'A'],
  right: ['ArrowRight', 'd', 'D'],
});
mitiru.input.start();

// --- 定数 ----------------------------------------------------------------
const W = 960, H = 540;
const PLAYER_SIZE = 32;
const PLAYER_SPEED = 240;     // px / sec
const TARGET_R = 12;

// --- 状態 ----------------------------------------------------------------
let player = { x: W / 2, y: H / 2 };
let target = randomTarget();
let score = 0;

function randomTarget() {
  return {
    x: 40 + Math.random() * (W - 80),
    y: 40 + Math.random() * (H - 80),
  };
}

// --- メインループ --------------------------------------------------------
const ctx = document.getElementById('stage').getContext('2d');
let last = performance.now();

function frame(now) {
  const dt = Math.min(0.05, (now - last) / 1000);
  last = now;

  step(dt);
  draw();

  requestAnimationFrame(frame);
}

function step(dt) {
  // 方向ベクトルを作る
  const dx = (mitiru.input.button('right') ? 1 : 0)
           - (mitiru.input.button('left')  ? 1 : 0);
  const dy = (mitiru.input.button('down')  ? 1 : 0)
           - (mitiru.input.button('up')    ? 1 : 0);

  // 斜め移動も同速度にする (ベクトル正規化)
  const len = Math.hypot(dx, dy) || 1;
  player = {
    x: player.x + (dx / len) * PLAYER_SPEED * dt,
    y: player.y + (dy / len) * PLAYER_SPEED * dt,
  };

  // 画面端でクランプ (壁との当たり判定)
  const half = PLAYER_SIZE / 2;
  player.x = Math.max(half, Math.min(W - half, player.x));
  player.y = Math.max(half, Math.min(H - half, player.y));

  // 目標との当たり判定 (中心同士の距離)
  const dist = Math.hypot(player.x - target.x, player.y - target.y);
  if (dist < (PLAYER_SIZE / 2) + TARGET_R) {
    score += 1;
    target = randomTarget();
    document.getElementById('score').textContent = score;
  }
}

function draw() {
  ctx.clearRect(0, 0, W, H);

  // target
  ctx.fillStyle = '#ffd24d';
  ctx.beginPath();
  ctx.arc(target.x, target.y, TARGET_R, 0, Math.PI * 2);
  ctx.fill();

  // player
  ctx.fillStyle = '#5be0a7';
  ctx.fillRect(player.x - PLAYER_SIZE / 2, player.y - PLAYER_SIZE / 2,
               PLAYER_SIZE, PLAYER_SIZE);
}

requestAnimationFrame(frame);

ポイント:

  • mitiru.input.setActionMap で 矢印キーと WASD を同じ “アクション” として宣言 すれば、両方が同時に効くようになります。プレイヤー側で「Arrow vs WASD」のような分岐コードを書く必要はありません。
  • 移動は 時間ベース (PLAYER_SPEED * dt) です。フレームレートが変わっても速さが変わりません。
  • 壁との当たり判定は単純なクランプで OK。複雑なステージは後で。

手順 5: ビルドして実行

mitiru run

矢印キーか WASD で緑の矩形が動き、黄色い丸に触れるとスコアが上がれば完成です。

何が分かったか

  • mitiru.input を使うと 入力デバイスの違いを 1 行も書かずに済む。アクションマップが意図を表現する。
  • ゲームループは 「状態を進める step()」と「現在の状態を描く draw()」を別関数に分ける と読みやすい。
  • 当たり判定は最初は単純なクランプや距離計算で十分。当たり判定が増えたら別ファイルに切り出します。

同じ仕組みは他ジャンルにも使える

このプロトタイプの骨は「入力 → 状態更新 → 衝突判定 → 描画」というループです。役割は同じまま、見せ方や中身を変えるとほぼあらゆる 2D ゲームの土台になります。

  • シューティング: 弾と敵をプールで持って、毎フレーム位置を進めて衝突を見る (shoot_em_up サンプル)。
  • パズル: 入力は離散 (1 マスずつ動く) になりますが、mitiru.input.pressed('right') のように 1 回押しを取れば実装できます。
  • アクション RPG: プレイヤーに HP を持たせ、目標を敵に置き換えると戦闘になります。
  • 物理パズル / ブロック崩し: ボールの速度ベクトルを保持し、壁と当たったら符号反転 (breakout サンプル)。

次の一歩

  • HP やゲームオーバー状態を入れる ⇒ HUD を 1 個増やす要領で、CEF 側に表示専用のバーを足すと自然です。
  • 効果音 ⇒ engine の audio API を呼ぶ (TODO: 次のチュートリアル候補)。
  • 状態を C++ 側に引き上げる ⇒ BridgeActionRouter 経由で gameplay を C++ に寄せると、JS は描画と入力通知だけになります。
  • 次のレッスン: 03 — セーブとロード に進むと、スコアや進行状況を保存できるようになります。
