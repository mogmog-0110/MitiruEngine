DISTRIBUTE

ゲームを渡せる形にまとめる

mitiru distを実行すると、完成したゲームをWindowsで起動できる配布フォルダが作られます。受け取った人は、追加のランタイムをインストールせず、トップにある実行ファイルをダブルクリックして遊べます。

ひとつのコマンドで配布物を作成

プロジェクトのフォルダでmitiru distを実行します。Releaseビルドの後、ゲームの実行に必要なファイルがdist/<名前>/へまとめられます。

  1. プロジェクトのフォルダでmitiru distを実行します。
  2. dist/<名前>/に、<名前>.exeとdata/が作られます。
  3. フォルダ全体、またはzipを渡します。受け取った人は<名前>.exeを起動します。

作成時の指定

mitiru dist              # dist/<名前>/ を作成 (assetsはひとつのファイルにまとめる)
mitiru dist --zip        # 配布フォルダとzipを作成
mitiru dist --onefile    # ひとつのexeにまとめる
mitiru dist --check      # 作った配布物を一時フォルダで動かして確かめる
mitiru dist --pack=false # assetsをフォルダのまま収録する
mitiru dist --bat        # ログ確認用の.batを追加
mitiru dist --debug      # Debugビルドを配る (自分のテスト機用)
mitiru dist --sign       # 自分のexeとDLLにコード署名する (証明書は環境変数で渡す)

作成されるフォルダ

既定では次の構成になります。トップの<名前>.exeは、コンソール画面を出さずにdata/mitiru_host.exeを呼び出す小さなランチャーです。

# dist/my-game/
my-game.exe
README.txt
THIRD_PARTY_NOTICES.txt
data/
  mitiru_host.exe
  launch.mtargs
  my_game/
    my_game.dll
    assets.mtpak
  vcruntime140.dll …ランタイムのDLL一式
my-game.exe ダブルクリックでゲームを起動します。コンソール画面は表示しません。
THIRD_PARTY_NOTICES.txt 第三者ライセンスの表記です。プロジェクトのTHIRD_PARTY_NOTICES.txtの後に、そのビルドがリンクしたライブラリと同梱したDLLの分だけをエンジンが書きます。
data/mitiru_host.exe ゲームを動かすホストです。
data/launch.mtargs ウィンドウサイズなどの起動引数を保存します。
my_game.dll 機械語に変換されたゲーム本体です。
assets.mtpak 画像、RML、RCSS、音をまとめたファイルです。
vcruntime140.dllなど Visual C++のランタイムです。mitiru distがゲームの読むDLLを調べて同梱します。

data/にはゲーム本体とランタイムが入っています。トップの実行ファイルと一緒に配布し、移動や削除は行いません。

受け取った人の操作

フォルダ全体をzipにするか、--zipで作成したzipを渡します。受け取った人はzipを展開し、<名前>.exeをダブルクリックします。必要なランタイムは配布物に含まれるため、別途インストールする必要はありません。

mitiru.tomlに記録したウィンドウサイズなどの設定は、ランチャーへ自動で反映されます。ログを確認する場合は、--batでコンソール画面を表示する.batも追加できます。

素材をひとつのファイルにまとめる

既定では、assets/内の画像、音、JSONなどをassets.mtpakへまとめ、個別のファイルを配布物から除きます。ゲームは起動時にこのファイルから直接読み込み、展開したファイルを保存しません。

RMLとRCSS (assets/ui/)、3Dモデル (.obj / .gltf / .glb / .fbx)、ナビメッシュはエンジンがファイルから直接読むため、フォルダのまま収録します。3Dモデルは初回の起動時に、描画用に変換した.clodをモデルの隣に保存します。

--pack=falseを指定した場合は、assets/がフォルダのまま収録され、各ファイルを確認できます。ゲーム本体の.dllは機械語であり、ソースコードは配布されません。

assets.mtpakは暗号化ではなく難読化です。内容を簡単に閲覧されることを防ぐための機能であり、強い秘匿が必要な用途には適しません。

セーブと設定の保存先

配布物のゲームは、セーブを%APPDATA%\<名前>\saves\、設定を%APPDATA%\<名前>\settings.jsonに保存します。配布フォルダの中には書き込まないため、書き込みできない場所に置いても動作し、配布物を更新してもセーブは残ります。

動作の確認

--checkを指定すると、作った配布物を一時フォルダへコピーし、開発用の環境変数とPATHを外した状態でheadlessで起動します。ファイルが読めないというログが出た場合や、ゲームが0以外で終了した場合は失敗として報告します。最後の画面はbuild/dist-check/<名前>.pngに、ログは同じ場所の.logに保存します。

ゲームが読むDLLが配布物にもWindowsにも無い場合は、mitiru distがエラーで止まります。Releaseの配布物がDebug版のランタイムを読む場合も同様です。

受け取った人のPCで起動に失敗した場合は、原因をメッセージで表示し、ログを%LOCALAPPDATA%\MitiruGames\<名前>\last_run.logに残します。

コード署名

--signを指定すると、Windows SDKのsigntoolで、トップの<名前>.exe、data/mitiru_host.exe、ゲームのDLLに署名します。--onefileでは、まとめたexeにも署名します。証明書は作者が用意し、設定は環境変数だけから読みます (リポジトリに証明書やパスワードを置かないため)。

MITIRU_SIGN_CERT_FILE.pfxの場所。パスワードはMITIRU_SIGN_CERT_PASSWORD
MITIRU_SIGN_CERT_THUMBPRINTWindowsの証明書ストアにある証明書の拇印 (上と片方だけ)
MITIRU_SIGN_TIMESTAMP_URLタイムスタンプ局。既定はhttp://timestamp.digicert.com
MITIRU_SIGNTOOLsigntool.exeの場所。無ければPATHとWindows SDKの中を探します

signtoolか証明書が見つからない場合は、ビルドを始める前にエラーで止まります。

落ちた時の報告

配布物のゲームが落ちると、minidump (.dmp)、報告 (.txt)、その時のログ (.log) を%LOCALAPPDATA%\MitiruGames\<名前>\crashes\に残します。次の起動で、報告を残した場所を画面で知らせます。

DLLの隣のship.jsonに送り先 ("crashReportUrl"、httpsのみ) を書いた場合は、送ってよいかを最初の1回だけ利用者に聞き、許された時だけ送ります。答えは設定 (privacy.crashReports) に残ります。送り方はbreakpad形式のmultipartなので、Sentryのminidumpの受け口などにそのまま送れます。詳しくはdocs/CRASH_REPORTS.mdにあります。

配布サイズ

配布物はゲームのDLLと実行環境で構成し、ブラウザエンジンは含みません。大きさの実測値はインストールページにあります。

現在の配布対象はWindows x64です。 mitiru distはWindows向けの実行ファイルを作成します。macOS版とLinux版は今後対応予定です。
