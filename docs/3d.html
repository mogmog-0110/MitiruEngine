3D

3D も、2D の上にのせて出す

MitiruEngine の正面は 2D + HTML/CSS ですが、3D も出せます。やり方は素直で、3D のシーンを CPU のソフトレンダラーで 1 枚の画像に焼き、その画像を Screen にそのまま貼るだけ。重い GPU の 3D 経路に頼らないので、2D の描画と同じ並びに 3D が混ざります。状態は「数値だけ」なので完全に決定的——録画も巻き戻しも、2D ゲームと同じように効きます。

やっていること — 3D を 1 枚の画像にして 2D へ貼る

3D の絵は、エンジン内蔵のソフトレンダラー DeferredPipeline が CPU で計算します（影・陰影・ハイライトまで）。出力先は画面ではなく RenderTexture——ただのピクセルの入れ物です。あとはそのピクセルを Screen::drawPixelGrid で画面へ貼れば、3D が 2D の 1 枚絵になります。HUD やメニューは、その上にいつもの 2D で重ねます。

コード — ふだんのゲームと同じ形

ゲームの形は 2D とまったく同じです。状態は struct に数値だけを持ち、update で動かし、draw で描く。3D を描くための道具（メッシュやパイプライン）は「描く部品」であって状態ではないので、struct の外（グローバル）に置きます——録画・巻き戻しのために、状態は数値だけに保つ決まりです（→ 決定論）。

#include <mitiru.hpp>
#include <mitiru/render/DeferredPipeline.hpp>   // CPU ソフトレンダラー
#include <mitiru/render/Scene3D.hpp>            // メッシュ + ライトの入れ物
using namespace mitiru;
namespace r = mitiru::render;

// 3D を描く道具は状態ではない → グローバルに置く（struct には入れない）
static r::DeferredPipeline g_pipe;
static r::RenderTexture    g_frame{512, 288};      // 3D を焼く先（16:9）
static const r::Mesh g_cube   = r::Mesh::createCube(1.0f);
static const r::Mesh g_ground = r::Mesh::createPlane(14.0f, 14.0f);

struct Hello3D {
    float t = 0, cubeX = 0, cubeZ = 0;          // 状態は数値だけ（決定的）

    void init() {
        g_pipe.initialize(512, 288, r::ShadowMapConfig{1024, 12.0f});  // 影マップ
    }

    void update(Input in, float dt) {
        t += dt;                                  // カメラ周回・立方体の回転に使う
        if (in.down(Key::Left))  cubeX -= 4.5f * dt;   // 矢印キーで立方体を動かす
        if (in.down(Key::Right)) cubeX += 4.5f * dt;
    }

    void draw(Screen& s) {
        // 1) 3D シーンを組んで、CPU で 1 枚の画像に焼く
        r::Scene3D scene;
        r::Material mat = r::Material::defaultMaterial();
        scene.addObject({&g_ground, mat, {0,0,0}, {0,0,0}, {1,1,1}});
        scene.addObject({&g_cube,   mat, {cubeX, 0.65f, cubeZ}, {0, t, 0}, {1,1,1}});
        scene.addLight(r::Light::directional({-0.5f, -1, -0.4f}));

        r::Camera3D cam;
        cam.setPosition({std::sin(t * 0.3f) * 11, 6.5f, std::cos(t * 0.3f) * 11});
        cam.setTarget({0, 0.8f, 0});
        cam.setAspectRatio(512.0f / 288.0f);
        g_pipe.render(scene, cam, g_frame);       // → g_frame に焼ける

        // 2) 焼いた画像を 2D としてそのまま画面へ貼る
        s.drawPixelGrid(Rect{0, 0, 1280, 720},
            (const std::uint32_t*)g_frame.pixels().data(),
            g_frame.width(), g_frame.height());

        // 3) HUD は 2D。3D の上に普通に重なる
        s.text("MitiruEngine 3D", 28, 22, color::White, 30);
    }
};

MITIRU_GAME(Hello3D)

完全版（影を落とすピラーや、立方体を追従して周回する球まで入ったもの）は、リポジトリの examples/hello3d/ にあります。上のデモはそれをそのまま動かしたものです。

決定的だから、録画も巻き戻しも効く。 3D の絵は「時刻 t と立方体の位置」だけから決まります。状態が数値だけなら、エンジンはそれを丸ごと保存・復元できる——つまりこの 3D ゲームも、2D と同じくホットリロード・タイムトラベル・リプレイの対象になります（→ ⑩ 決定論）。GPU のフレームに依存しないので、結果はどの環境でも同じです。

向いていること・いないこと

これは「2D に 3D を混ぜる」「小〜中規模の 3D を出す」ための道具です。CPU で 1 ピクセルずつ計算するので、内部解像度は控えめ（デモは 512×288 を画面いっぱいに拡大）にして、形のはっきりした絵に向きます。

向いている2D ゲームに 3D の小物・背景・ミニ表示を混ぜる／立方体・球・板・読み込んだメッシュを並べる程度の 3D／決定論や巻き戻しが要る 3D
向いていない大量ポリゴンや高解像度を実時間で回す本格 3D／GPU シェーダー前提の重い表現。MitiruEngine の正面はあくまで 2D + HTML/CSS です

「3D ゲームエンジン」ではなく、「2D エンジンで 3D も出せる」という位置づけです。やりたいことが本格 3D に寄るなら、別のエンジンの方が向いています——そこは正直に。
