TUTORIAL

はじめてのゲーム

この 1 本で「スター・キャッチ」を作ります。下のプレイヤーを左右に動かし、落ちてくる星をキャッチしてスコアを伸ばす — 単純なゲームです。覚えるのは struct・update・draw の 3 つだけ。前半「まず動かす」で mitiru run して遊べるところまで一気に進み、後半「育てる」でホットリロード・観察窓・HTML/CSS の HUD へ広げます。読み終わる頃には、自分のゲームを作る土台ができています。

Part A・まず動かす — 作るもの

下のプレイヤーを左右に動かして、上から落ちてくる星をキャッチするとスコアが増えます。たまに混ざる爆弾を取ってしまうと GAME OVER、Space で再開。星を取った瞬間だけ、プレイヤーが一瞬うれしそうな顔になります。まずは動いているところを見てください。

このページの「スター・キャッチ」は、mitiru new my-catch で作る自分のプロジェクトです。同梱サンプルを動かすのではなく、空のひな型から自分で書き上げます。前半は理屈を後回しにして、とにかく mitiru run で遊べる状態を目指します。

ゲームは 3 つでできている

どんなゲームも、だいたいこの 3 つの組み合わせでできています。この章で書くのは update と draw の中身だけ。残りはエンジンの仕事です。

状態を持つstruct

プレイヤーの位置・スコア・落ちてくる物の場所など「いまどうなっているか」を 1 つの struct にまとめて持つ。

動かすupdate

毎フレーム呼ばれる関数。入力を読んでプレイヤーを動かし、星や爆弾を落とし、当たり判定をする。

描くdraw

毎フレーム呼ばれる関数。いまの状態を見て、スプライトや文字を画面に描く。

エンジンが毎フレーム、自動でこのループを回します:

  入力 (キー・マウス・パッド)
        │
        ▼
  update(in, hud, dt)   // 状態を進める ← ここを書く
        │
        ▼
  状態 (struct CatchGame)
        │
        ▼
  draw(s)              // 状態を描く   ← ここを書く
        │
        ▼
  画面 (1280 × 720)
        ↺  1 秒に約 60 回くり返す

状態を struct に置いて、update で動かして、draw で描く。以降の Step は、この順番でそのまま埋めていくだけです。

Step 1 — プロジェクトを作る

mitiru new my-catch
cd my-catch

mitiru new を実行すると、my-catch/ の中にプロジェクトのひな型ができます。書き換えるのは src/main.cpp ただ 1 つ。最初の数行はこう書きはじめます。using namespace mitiru; と書いておくと、Key や color を短く書けます。

#include <algorithm>                      // std::clamp（画面外に出ないよう挟む）
#include <string>
#include <mitiru/core/Random.hpp>       // 乱数 mitiru::Random
#include <mitiru/module/Game.hpp>      // ゲームの入口・Input・Hud・Screen・色
using namespace mitiru;
乱数は mitiru::Random。Random rng{1234}; のように seed（種）を渡して置きます。同じ seed なら毎回同じ並びの乱数が出る決まりで、これがあとで「録画したプレイを完全に同じように再生する」のに効きます。使い方は rng.nextFloat(60, 1200)（範囲の小数）・rng.nextBool(0.12f)（12% の確率で true）。このゲームでは、星をどこに出すか・たまに爆弾を混ぜるか、の決定に使います。

Step 2 — 状態を struct に書く

このゲームが覚えておくのは「プレイヤーの位置」「落ちてくる物」「スコア」など。それを 1 個の struct にまとめます。乱数の rng もメンバとして持っておきます。後で書き換えて遊ぶ 3 つの数値（速度・落下・背景色）は、ファイルの先頭にまとめて定数で置いておきます。

// ── チューニング: この値を書き換えて保存するとホットリロードで即反映される ──
constexpr float       kPlayerSpeed = 600.0f;   // プレイヤーの左右速度
constexpr float       kFallSpeed   = 300.0f;   // 落下スピード
constexpr sgc::Colorf kBgTop   {0.28f, 0.34f, 0.56f, 1.0f};   // 背景グラデ 上
constexpr sgc::Colorf kBgBottom{0.80f, 0.74f, 0.86f, 1.0f};   // 背景グラデ 下

// 落ちてくる物 1 個分。kind: 0=星(良) / 1=爆弾(悪)
struct Item { float x, y; int kind; bool alive; };

struct CatchGame {
    float  playerX = 640;       // プレイヤーの左右位置（中心）
    Item   items[24] {};        // 落ちてくる物は最大 24 個（全部 alive=false で開始）
    int    score = 0;
    bool   over = false;         // ゲームオーバーか
    float  spawnIn = 0.0f;        // 次の落下物を出すまでの残り秒
    float  happyTimer = 0.0f;     // 星を取った直後、喜び表情を出す残り秒
    Random rng{1234};            // 乱数（seed 固定 = リプレイ決定論）
    // ↓ update / draw はこの下に書く
};

状態をこの 1 つの struct にまとめておくと、エンジンがこれを預かってくれます。だから後で「コードを書き換えても状態は保ったまま」「プレイを録画して再生」「過去に巻き戻す」といった便利機能がそのまま使えます（仕組みは 後半のホットリロードの章でまとめて説明します。いまは気にしなくて大丈夫）。happyTimer は「星を取ってから少しの間だけ、うれしい顔を見せる」ためのタイマーです。

Step 3 — 動かす（update）を書く

毎フレーム呼ばれます。in から入力を読み、dt（前フレームからの経過秒）を使って動かします。やることは 3 つ — ① プレイヤーを動かす ② ときどき星か爆弾を出す ③ 落として当たり判定。struct のメンバ関数として書きます。引数の hud は後半の観察・演出で使うもので、いまは置いておくだけで構いません。

void update(Input in, Hud hud, float dt) {
    if (over) {                                // ゲームオーバー中は決定キーで再開だけ
        if (in.confirmPressed()) { *this = CatchGame{}; }
        return;
    }

    if (happyTimer > 0) happyTimer -= dt;       // 喜び表情の残り時間を減らす

    // ① プレイヤーを左右に。in.move() が矢印 / WASD / パッド左スティックを 1 つに合成する
    playerX += in.move().x * kPlayerSpeed * dt;
    playerX = std::clamp(playerX, 48.0f, 1232.0f);   // 画面外に出ない（画像幅の半分ぶん内側）

    // ② 0.6 秒ごとに、空いている枠へ星か爆弾を上から出す（12% で爆弾）
    spawnIn -= dt;
    if (spawnIn <= 0) {
        spawnIn = 0.6f;
        for (Item& it : items)
            if (!it.alive) {
                it.alive = true;
                it.x = rng.nextFloat(60, 1220);
                it.y = -40;
                it.kind = rng.nextBool(0.12f) ? 1 : 0;   // 1=爆弾, 0=星
                break;
            }
    }

    // ③ 落として、プレイヤーと重なったか調べる（判定は上半身あたり）
    sgc::Rectf player{playerX - 46, 568, 92, 84};   // {x, y, 幅, 高さ}
    for (Item& it : items) {
        if (!it.alive) continue;
        it.y += kFallSpeed * dt;                // 下へ落とす
        sgc::Rectf box{it.x - 28, it.y - 28, 56, 56};   // 落下物（56px）の判定枠
        if (player.intersects(box)) {           // キャッチした
            if (it.kind == 1) over = true;           // 爆弾 → ゲームオーバー
            else { score += 1; happyTimer = 0.35f; } // 星 → +1 して喜ぶ
            it.alive = false;
            continue;
        }
        if (it.y > 760) it.alive = false;        // 下に抜けたら消す
    }
}

入力の読み方: in.move() は移動入力を 1 つにまとめて返します（.x と .y、各 −1〜1）。矢印キーでも WASD でもゲームパッドの左スティックでも、これ 1 つで全部に対応できます。だから playerX += in.move().x * kPlayerSpeed * dt; と書くだけで、どのデバイスでも左右移動になります。再開の in.confirmPressed() は「決定」を押した瞬間だけ true（Space / Z / Enter / パッド A）です。

物を出す: items は最大 24 個の置き場。空いている（!alive）枠を 1 つ見つけて alive = true にし、出現 x を rng.nextFloat(60, 1220) でランダムに、rng.nextBool(0.12f)（12%）で爆弾かどうかを決めます。やり直しは *this = CatchGame{};（状態をまるごと初期値に戻す）の 1 行で済みます。

当たり判定はエンジンが持っています。 四角どうしが重なったかは sgc::Rectf（{x, y, 幅, 高さ}）の .intersects(他の矩形) で一発。点が矩形の中にあるかは .contains(点)。ここでは「プレイヤーの判定枠」と「落下物の判定枠」が重なったらキャッチ、としています。判定枠は上半身あたり（足元より少し上）に置いています。

Step 4 — 描く（draw）とスプライト

毎フレーム呼ばれます。s（画面）に絵を描きます。座標は左上が (0, 0)、右下が (1280, 720) です。ここで初めてスプライト（画像）を使います — プレイヤーも星も爆弾も PNG 画像です。

void draw(Screen& s) {
    // 背景: 上→下のグラデーション。色は先頭の kBgTop / kBgBottom
    s.drawGradientRect(sgc::Rectf{0, 0, 1280, 720}, kBgTop, kBgBottom);

    // 落下物（星 / 爆弾）をスプライトで描く。id で画像を指定。56px 画像なので
    // 中心 (it.x, it.y) から 28 引いた所を左上にする
    for (Item& it : items)
        if (it.alive) s.sprite(it.kind == 1 ? "bomb" : "star", it.x - 28, it.y - 28);

    // プレイヤー（96×130）。星を取った直後だけ喜び表情に切り替える
    const char* who = (happyTimer > 0) ? "player_happy" : "player";
    s.sprite(who, playerX - 48, 548);          // 画像の幅 96 の半分ぶん左へ寄せて中心合わせ

    // スコアを文字で描く — まだ HTML は使いません
    s.text("SCORE " + std::to_string(score), 24, 20, color::White, 24);

    if (over) {                                // ゲームオーバー表示（画面幅から文字幅を引いて中央へ）
        float w = s.measureText("GAME OVER", 44).x;
        s.text("GAME OVER", (1280 - w) / 2, 312, color::White, 44);
        float w2 = s.measureText("press SPACE to retry", 20).x;
        s.text("press SPACE to retry", (1280 - w2) / 2, 376, color::Gray, 20);
    }
}

描き方: 画像は s.sprite("id", x, y) で描きます。"id" は画像ファイルの名前、x, y は描く左上の座標です。背景は s.drawGradientRect(矩形, 上の色, 下の色) で上から下へ色が変わる帯。色は sgc::Colorf{r, g, b, a}（各 0〜1）で書きます。文字は s.text("文字", x, y, 色, 大きさ) で、color::White のような名前の色も使えます。

中心合わせのコツ: スプライトも文字も左上座標で描かれます。中心を (x, y) に置きたいときは、幅の半分を引いた位置を左上に渡します。星・爆弾は幅 56px なので -28、プレイヤーは幅 96px なので -48。文字を中央に置くときも同じ考え方で、s.measureText("文字", 大きさ) が実際の文字幅を返すので、(画面幅 − 文字幅) / 2 を左上 x にすればフォントが変わってもきっちり中央に収まります。

スプライトは画像を id で描く

s.sprite("player", x, y) の "player" は画像ファイルの名前です。エンジンは、ゲームの隣にある assets/sprites/player.png を探して描きます。"star" なら assets/sprites/star.png、というふうに id → assets/sprites/<id>.png で素直に対応します。だから絵を増やすときは、PNG をフォルダに置いて、その名前を sprite() に渡すだけです。

このゲームで使う画像は 4 つ。すべて透過 PNG（背景が透けるので重ねても四角い縁が出ません）です:

assets/sprites/player.pngプレイヤー（96 × 130）。ふだんの姿
assets/sprites/player_happy.pngプレイヤーの喜び表情。星を取った直後だけ表示
assets/sprites/star.png星（56 × 56）。取ると +SCORE
assets/sprites/bomb.png爆弾（56 × 56）。取ると GAME OVER

表情の切り替えは「どの id を描くか」を変えるだけです。draw で happyTimer > 0 のときは "player_happy"、ふだんは "player" を渡しています。新しい状態を作らなくても、同じ位置に別の画像を出せば「表情が変わった」ように見えます。

ここまで書くと、画面はこう育ちます:

この 4 枚をダウンロード

下の画像をそのまま使えます。クリックで保存して、プロジェクトの assets/sprites/ に同じ名前（player.png / player_happy.png / star.png / bomb.png）で置けば動きます。自分の絵に描き替えても、名前さえ合っていれば OK です。

Step 5 — 仕上げて動かす

最後に 1 行、このゲームを DLL の入口に結びつけます。

MITIRU_GAME(CatchGame)   // これだけ

MitiruEngine では、書いたゲームは DLL（差し替え可能な部品）としてビルドされ、mitiru_host という実行ファイルがそれを読み込んで動かします。ホストとゲームの間は、決まった入口関数でやり取りします。MITIRU_GAME(CatchGame) は、その入口関数を自動で書いてくれるマクロです。中では「CatchGame を 1 個作って、毎フレーム update と draw を呼んでね」という配線が展開されるので、書くのは update と draw だけでよく、面倒な決まり文句（C の関数シグネチャや extern "C" など）は一切書かずに済みます。この「ゲーム＝差し替え可能な DLL」という形が、後半に出てくるホットリロードを可能にしています。

mitiru run

窓が開いて、ゲームが動きます。矢印キー（か WASD・パッド）でプレイヤーを動かして、落ちてくる星をキャッチしてみてください。星は +SCORE、爆弾を取ると GAME OVER、Space で再開です。ここまでが前半 — もう遊べます。

全コード — このまま貼れば動く

ここまでの Step を 1 つにまとめた、そのまま遊べる全コードです。src/main.cpp を丸ごとこれに置き換えて mitiru run。長いので折りたたんであります — 開いてコピーしてください。（assets/sprites/ に 4 つの PNG を置くのを忘れずに。）

本文のステップでは省いた行も、ここには入っています。frame（経過フレーム数）と末尾の MITIRU_REFLECT / MITIRU_GAME_SERIES は、後半の観察窓やタイムトラベルでスコアの履歴グラフを出すための申告です。前半を遊ぶだけなら気にせず、後半「観察する」で意味が分かります。

全コード src/main.cpp を開く（コピペ用） 
// catch — スター・キャッチ

#include <algorithm>
#include <cstdint>
#include <cstdio>
#include <string>

#include <mitiru/core/Random.hpp>
#include <mitiru/module/Game.hpp>

using namespace mitiru;

// ── チューニング: この値を書き換えて保存するとホットリロードで即反映される ──
constexpr float       kPlayerSpeed = 600.0f;                   // プレイヤーの左右速度
constexpr float       kFallSpeed   = 300.0f;                   // 落下スピード
constexpr sgc::Colorf kBgTop   {0.28f, 0.34f, 0.56f, 1.0f};    // 背景グラデ 上
constexpr sgc::Colorf kBgBottom{0.80f, 0.74f, 0.86f, 1.0f};    // 背景グラデ 下

// ── 画面と大きさ ────────────────────────────────────────────────────────────
constexpr float kScreenW  = 1280.0f;
constexpr float kScreenH  = 720.0f;
constexpr float kPlayerFeetY = 678.0f; // プレイヤーの足元の y
constexpr float kPlayerW   = 96.0f;    // プレイヤー画像の幅 (px)
constexpr float kPlayerH   = 130.0f;   // プレイヤー画像の高さ (px)
constexpr float kItemR     = 28.0f;    // 落下物スプライト (56px) の半径
constexpr int   kMaxItems = 24;       // 同時に出せる落下物の上限

// 落ちてくる物 1 個 (flat POD)。kind: 0=星(良) / 1=爆弾(悪)。
struct Item { float x, y; int kind; bool alive; };

// ── ゲームの状態 (flat POD — ポインタ・vector・string を持たない) ─────────────
struct CatchGame
{
    float         playerX = kScreenW * 0.5f;   // プレイヤーの左右位置 (中心)
    Item          items[kMaxItems] {};         // 落下物 (全部 alive=false で開始)
    int           score   = 0;
    bool          over    = false;
    float         spawnIn = 0.0f;              // 次の落下物までの残り秒
    float         happyTimer = 0.0f;          // 星を取った直後の喜び表情の残り秒
    std::uint32_t frame   = 0;                // 経過フレーム (タイムトラベルの横軸)
    bool          opened  = false;            // ツール窓を開いたか (1 回だけ)
    Random        rng{1234};                  // 乱数 (seed 固定でリプレイ決定論)

    // 毎フレーム呼ばれる。in=入力 / hud=別窓 UI / dt=前フレームからの経過秒。
    void update(Input in, Hud hud, float dt)
    {
        // 別窓の inspector を「コードから」開く (1 回だけ)。CLI は要らない。
        // 観察したいものに合わせ Tool::TimeTravel / Tool::Perf などに変えるだけ。
        if (!opened) { hud.open(Tool::Inspector); opened = true; }

        if (over)   // ゲームオーバー中は決定キーで再開だけ (開いた窓は閉じない)
        {
            if (in.confirmPressed()) { CatchGame fresh{}; fresh.opened = opened; *this = fresh; }
            return;
        }

        if (happyTimer > 0.0f) { happyTimer -= dt; }   // 喜び表情の残り時間を減らす
        ++frame;

        // ① プレイヤーを左右に (矢印 / WASD / パッド左スティック、全部 move() が合成)
        playerX += in.move().x * kPlayerSpeed * dt;
        playerX = std::clamp(playerX, kPlayerW * 0.5f, kScreenW - kPlayerW * 0.5f);

        // ② 0.6 秒ごとに、空き枠へ星か爆弾を上から出す (時々 爆弾)
        spawnIn -= dt;
        if (spawnIn <= 0.0f)
        {
            spawnIn = 0.6f;
            for (Item& it : items)
            {
                if (!it.alive)
                {
                    it.alive = true;
                    it.x     = rng.nextFloat(60.0f, kScreenW - 60.0f);
                    it.y     = -40.0f;
                    it.kind  = rng.nextBool(0.12f) ? 1 : 0;
                    break;
                }
            }
        }

        // ③ 落として、プレイヤーと重なったか調べる (判定はプレイヤーの上半身あたり)
        const sgc::Rectf player{playerX - 46.0f, kPlayerFeetY - 110.0f, 92.0f, 84.0f};
        for (Item& it : items)
        {
            if (!it.alive) { continue; }
            it.y += kFallSpeed * dt;
            const sgc::Rectf box{it.x - kItemR, it.y - kItemR, kItemR * 2.0f, kItemR * 2.0f};
            if (player.intersects(box))               // キャッチ
            {
                if (it.kind == 1) { over = true; }                 // 爆弾 → 終了
                else { score += 1; happyTimer = 0.35f; }           // 星 → +score & 喜ぶ
                it.alive = false;
                continue;
            }
            if (it.y > kScreenH + 40.0f) { it.alive = false; }   // 下に抜けた
        }

        // inspector へ観察データを送る (開いている時だけ映る。閉じていれば無視される)。
        char json[96];
        std::snprintf(json, sizeof(json), "{\"score\":%d,\"playerX\":%d}", score, static_cast<int>(playerX));
        hud.watch("catch", "Catch", json);
    }

    // 毎フレーム呼ばれる。s に絵を描く。座標は左上 (0,0)・右下 (1280,720)。
    void draw(Screen& s)
    {
        // 背景: 上→下のやさしいグラデーション (色は上の kBgTop / kBgBottom)。
        s.drawGradientRect(sgc::Rectf{0.0f, 0.0f, kScreenW, kScreenH}, kBgTop, kBgBottom);

        // 落下物 (星 / 爆弾) をスプライトで描く。id は assets/sprites/<id>.png。
        // sprite(id, 左上x, 左上y) — 56px 画像。中心を (x,y) に置く。
        for (const Item& it : items)
        {
            if (!it.alive) { continue; }
            s.sprite(it.kind == 1 ? "bomb" : "star", it.x - kItemR, it.y - kItemR);
        }

        // プレイヤー (96×130)。星を取った直後だけ喜ぶ表情に切り替える。
        const char* who = (happyTimer > 0.0f) ? "player_happy" : "player";
        s.sprite(who, playerX - kPlayerW * 0.5f, kPlayerFeetY - kPlayerH);

        s.text("SCORE " + std::to_string(score), 24, 20, color::White, 24);

        if (over)   // ゲームオーバー表示 (画面幅から実テキスト幅を引いて中央へ)
        {
            const float goW = s.measureText("GAME OVER", 44.0f).x;
            s.text("GAME OVER", (kScreenW - goW) * 0.5f, 312.0f, color::White, 44);
            const float subW = s.measureText("press SPACE to retry", 20.0f).x;
            s.text("press SPACE to retry", (kScreenW - subW) * 0.5f, 376.0f, color::Gray, 20);
        }
    }
};

// ── タイムトラベル / inspector 用の申告 ──────────────────────────────────────
// GameMemory から値を 1 つ引く関数 (DLL 境界を安全に渡せる double(*)(const void*))。
double scoreProbe(const void* m)   { return static_cast<const CatchGame*>(m)->score; }
double playerXProbe(const void* m) { return static_cast<const CatchGame*>(m)->playerX; }

// inspector に出す GameMemory のスカラ場 (ADR 0018)。
MITIRU_REFLECT(CatchGame, playerX, score, over, frame, spawnIn, happyTimer);

// これ 1 つで DLL の入口 + time-travel 観測が出来る (host が CatchGame を 1 個作り
// update/draw を回し、GameMemory ring × probe で score / X の履歴を自動生成する)。
MITIRU_GAME_SERIES(CatchGame,
    { "score", "Score",    &scoreProbe,   0.0, 0 },
    { "x",     "Player X", &playerXProbe, 0.0, 0 });

これで完成です。まずはこれを動かしてから、先頭の kPlayerSpeed / kFallSpeed / 背景色や、出現間隔 0.6・爆弾の確率 0.12f を変えて手応えを確かめてみてください。その「変えて、すぐ確かめる」を速く回す方法が、後半の最初のテーマです。

Part B・育てる — ホットリロードで止めずに差し替える

ここからは、動いたゲームを育てる話です。まずは mitiru run の代わりに mitiru watch で起動してみてください。すると、src/ のコードを保存した瞬間に、ゲームを止めずに新しいコードへ差し替わります。これをホットリロードと呼びます。

仕組みはこうです。コードを保存すると、ゲームの DLL だけが素早く再ビルドされ（数秒）、走っている mitiru_host がそれをその場で差し替えます。ホストは再起動しないので、いまの状態（スコア・落下物の位置など）はそのまま残ります。「作り直して最初から」ではなく「遊んだまま中身だけ入れ替わる」のがホットリロードです。

なぜ状態が消えないのか — flat POD という形

状態が消えないのは、Step 2 で状態を 1 個の struct CatchGame にまとめ、それをエンジンが預かっているからです。エンジンはこのゲーム状態をまるごとコピーして保存・復元します。だから、預かったデータを新しいコードへそのまま渡せます。

これが成り立つには、ゲーム状態が「ただのデータ」＝仮想関数やポインタを持たない、コピーできる素直な型（flat POD）であってほしい。struct CatchGame はそのための形です。ここで効いているのが Step 4 の「絵はゲームが持たず、id で参照するだけ」という設計 — 画像（テクスチャ）はエンジン側がまとめて持ち、ゲームは "player" という文字列を渡すだけなので、struct は Texture のような重い物を抱えず素直なまま保てます。状態をまるごとコピーできる、この素直さが、巻き戻し・録画再生・後述の観察窓を同じ土台から生んでいます。

なお、これはトップのゲーム状態の話です。中で使う部品（敵・弾など）は普通に class で書いて構いません。トップの状態だけ素直に保つ、という住み分けです。

3 つの値を、走らせたまま書き換える

Step 2 で先頭にまとめた 3 つの値を、mitiru watch 中に順に書き換えてみましょう。ゲームは落ちずに、その場で手応えが変わります:

  • kPlayerSpeed 600 → 1400 … プレイヤーがきびきび動く
  • kFallSpeed 300 → 820 … 星が速く落ちて難しくなる
  • kBgTop / kBgBottom の色を変える … 背景が夕焼けに変わる

書き間違えてビルドが壊れても大丈夫です。エラーが画面に出て、ゲームは前のコードで動き続けます。直して保存すれば元に戻るので、コンソールと往復する必要はありません。

絵も、走らせたまま差し替えられる

ホットリロードはコードだけではありません。mitiru watch で動かしながら assets/sprites/player.png を別の絵に差し替えて保存すると、走っているゲームのプレイヤーがその場で新しい絵に変わります。ビルドも要りません — 絵を直して保存するだけで画面に反映されるので、お絵かきと確認の往復も速く回せます。

変わるもの・変わらないもの

「何が反映されて、何が残るか」は、その値がコードに焼き込まれるものなのか、実行中の状態なのかで決まります。3 つに分けて覚えると迷いません。

反映される
code		constexpr の定数（kPlayerSpeed など）・update / draw のロジック・描き方・スプライトの画像。これらは新しい DLL のコードや絵に焼き込まれて丸ごと入れ替わるので、保存するたびに即反映されます。この章でやってきたのは全部これです。
残る（＝書き換えても効かない）
state		struct のいまの値（score・playerX・落下物の位置など）。状態はエンジンが預かったまま新しいコードへ渡されるので、走行中の値はそのまま残ります。だから初期値の playerX = 640 を 100 に書き換えても、走っているプレイヤーは動きません（再起動して初めて効きます）。
壊れる／リセット
layout		struct にフィールドを足す・消す・並べ替える・型を変える。状態の形が変わると、預かっていたデータが新しい形に合わず壊れます（＝状態がリセット）。形を変えたいときは再起動が安全です。
覚え方: 数値や条件の調整は止めずに何度でも。状態の形（struct のフィールド）を変えたときだけ再起動。この心地よいループ全体を、状態を 1 つの struct にまとめてエンジンに預ける形（MITIRU_GAME）が支えています。

観察する — いまの状態を窓で見る

ゲームを作っていると「いまどうなってる?」が気になります。MitiruEngine は、巨大なエディタを開く代わりに必要な情報だけを小さな独立ウィンドウに出します。しかも開くのはコードから — コマンドではなく、ゲームのコードに 1 行書くだけです。

コードから窓を開く

update に渡される hud に「この窓を開いて」とお願いするだけです。Step 3 で update(Input in, Hud hud, float dt) の形にしておいたので、もう hud は手元にあります:

void update(Input in, Hud hud, float dt) {
    hud.open(Tool::Inspector);   // 状態をのぞく窓を開く
    // …いつもの update…
}
update は毎フレーム呼ばれますが、同じ窓は 1 回しか開きません（エンジンが重複を弾きます）。だから開きたい所に 1 行書くだけで OK。Tool::Inspector を Tool::Perf などに変えれば、開く窓が変わります。コマンドを打つ必要はなく、どの窓を使うかがコードに残るので、後で読んでも分かります。

inspector に状態が映る

hud.open(Tool::Inspector) で開く窓には、ゲームの状態がそのまま並びます。struct のフィールド（playerX・score・frame…）、hud.watch で送った値、履歴グラフまで、ゲームの隣でライブに動きます。

状態を 1 個の struct に置いているおかげで、エンジンは毎フレームの状態をそのまま記録できます。だから「状態を見る」だけでなく、過去に巻き戻したり、AI に全状態を読ませたりも、同じ struct から生えてきます。inspector のほかにも、入力の生値・過去フレームへの巻き戻し・録画再生・fps 計測・音量 VU などの窓があり、すべて hud.open(Tool::…) の Tool:: を変えるだけで開きます。それぞれの窓と、AI にゲームの全状態を読ませる AI Lens は、機能リファレンスのデバッグ窓・AI Lens の章にまとめてあります。

大切なのは考え方のほうです。巨大なエディタは開かず、1 ツール＝1 つの関心事＝1 つの窓。必要なものだけを画面に出す、というのが MitiruEngine の流儀です。

バグを窓で見つけて直す

観察窓がいちばん役に立つのは、バグに詰まったときです。先ほどの inspector を「原因調べ」に使う応用編として、わざとおかしな動きを入れて、窓で原因を見つけて直すまでをやってみます。

おかしな動きを入れてみる

落下速度を、うっかり毎フレーム足し続けてしまった、という想定です（= のつもりが +=）。struct CatchGame に float fallSpeed = 300.0f; を足して、落下処理をこう書きます:

fallSpeed += 4.0f;                 // 毎フレーム +4 ずつ増えてしまう
for (Item& it : items) {
    if (it.alive) it.y += fallSpeed * dt;
}

最初の数秒は普通に遊べますが、すぐに星が取れない速さになります。画面を見ても、なぜ加速するのかは分かりません。数字が見えないからです。

① perf 窓で「重いだけ」かを切り分ける

まず hud.open(Tool::Perf) を足して perf 窓を開きます。見ると fps は 60、ms も 16.6 のまま — 描画が重いのではなく、計算（ロジック）の問題だと分かります。「重い」と「計算がおかしい」は別の問題で、perf で fps が正常と分かれば描画やパフォーマンスは原因から外せます。これだけで調べる範囲が狭まります。

② inspector に値を送って中を見る

中の値を見るには、見たい値を inspector に送ります。hud.watch で名前を付けて送るだけです:

hud.watch("game", "Catch", std::to_string(fallSpeed).c_str());   // inspector 窓へ送る

hud.open(Tool::Inspector) で開くと、送った値が watch の第 2 引数の名前（ここでは Catch）でまとまって並びます。プレイすると fallSpeed が 300 → 436 → 1200 → 3400 … と増え続けているのが見えます。一定のはずの値が毎フレーム増えている — これが原因です。複数の値を一度に並べたいときは JSON 文字列（{"fallSpeed": …, "score": …}）を組んで渡せますが、まずは 1 値で十分です。

③ 直す

+= をやめて、毎フレーム同じ値にすれば直ります:

fallSpeed = 300.0f;                // 毎フレーム同じ速さに戻す
for (Item& it : items) {
    if (it.alive) it.y += fallSpeed * dt;
}

mitiru watch で動かしていれば、保存した瞬間に反映されます。inspector を開いたまま見ると、fallSpeed が増えなくなったのが確認できます。流れはいつもこれ — perf で切り分け → inspector で値を見る → 直す → 窓で確認。中が見えると、原因にたどり着きやすくなります。

便利機能: コードからスクショ。「この瞬間の画面を残したい」ときは、hud.screenshot(); を 1 行呼ぶだけで、そのフレームの画面が画像ファイルに保存されます。たとえば if (over) hud.screenshot(); でゲームオーバーの瞬間だけ自動保存、といった使い方ができます（バグ報告や、AI に画面を見せて確認してもらうのにも便利）。

道具箱 — 覚えておくと便利な道具

ゲームを書くとき、触るのは主に 3 つのオブジェクトだけです。update(Input in, Hud hud, float dt) の in と hud、そして draw(Screen& s) の s。それぞれ「よく使う道具」を並べておきます — この一覧がエンジンでできることのだいたい全部です。困ったらここに戻ってきてください。

in — 入力を読む（Input）

in.move()移動入力を 1 つに合成（矢印 / WASD / 左スティック）。.x .y 各 −1〜1。x += in.move().x * speed * dt
in.confirmPressed()「決定」を押した瞬間（Space / Z / Enter / パッド A）。再開・メニュー送りなど
in.down(Key::Left)キーが押されている間ずっと true（個別キーが要るとき）
in.pressed(Key::Space)押した瞬間だけ true / in.released(Key::Z) は離した瞬間
in.mouseDown(0) / mouseX() / mouseY()マウスのボタンと座標（0=左 1=右 2=中）
in.padDown(Pad::A) / leftStick()ゲームパッド（つながっていれば自動で使える）

hud — 画面に送る・音・演出・道具（Hud）

hud.set("view.hud.score", score)HTML の表示へ値を送る（次の章で詳しく）
hud.play("hit")効果音を鳴らす（hud.play("hit", 0.6f) で音量指定）
hud.flash(color::White)画面を一瞬フラッシュ（被弾演出など）
hud.screenshot()その瞬間の画面を画像保存。if (over) hud.screenshot(); でゲームオーバーだけ自動保存
hud.open(Tool::Inspector)独立ウィンドウを開く（何度呼んでも 1 回だけ開く）
hud.watch("game", "Catch", json)inspector に好きな値を送る（さっきのデバッグで使ったもの）
hud.quit()ゲームを終了する

s — 画面に描く（Screen）

s.sprite("player", x, y)画像を描く。id は assets/sprites/<id>.png。(x, y) は左上。s.sprite(id, x, y, scale) で拡大縮小
s.drawGradientRect(rect, top, bottom)上→下のグラデーション矩形（背景に）。色は sgc::Colorf{r,g,b,a}
s.measureText("文字", 44)描いたときの文字の幅・高さを返す。(1280 - w)/2 で中央寄せ
s.drawRect(x, y, w, h, color::Red)四角を描く（drawRectCentered は中心指定版）
s.text("SCORE", x, y, color::White, 24)文字を描く
ぜんぶ一気に覚えなくて OK。「こういうことできないかな?」と思ったらこの一覧を見る、くらいで十分です。入力は in、音や演出や道具は hud、描画は s — 3 つのどれかに必ず入っています。

見た目を HTML / CSS にする

いまスコアは s.text(...) で C++ から直接描いています。これを HTML と CSS の HUD に置き換えられます。ゲームのルール（C++）はそのまま、見た目だけを Web の書き方で作り直せます。

画面はどこに書く? — assets/scene.html

mitiru new で作ったプロジェクトは、こうなっています。ロジックは src/main.cpp（C++）、画面は assets/scene.html（HTML / CSS）、絵は assets/sprites/（PNG） — 触るのはこのあたりだけです。

my-catch/
├─ mitiru.toml          # 設定（ウィンドウサイズなど）
├─ src/
│  └─ main.cpp          # ← ゲームのロジック（C++。前半まで書いていた所）
└─ assets/
   ├─ scene.html        # ← 画面（HTML/CSS）。これが HUD の入口
   └─ sprites/          # ← スプライト（PNG）。s.sprite("id") の id がここに対応
      ├─ player.png
      ├─ player_happy.png
      ├─ star.png
      └─ bomb.png

assets/scene.html が HTML のエントリポイントです。エンジンはゲーム起動時にこの 1 枚を読み込み、ゲーム画面の上に透明なオーバーレイとして重ねます。だから C++ が描いた絵（背景・星・プレイヤー）の上に、HTML の HUD が乗ります。

scene.html を書く（CSS もこの中）

scene.html は普通の HTML ファイルです。CSS は <style> の中に書きます（別ファイルにしても OK）。末尾の <script> 2 行は、エンジンが値を流し込むための付属部品 — mitiru build が mitiru_runtime/ を隣に自動コピーするので、この 2 行をそのまま書くだけです。

<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <style>
    /* ← CSS はここに書く。影・角丸・色、Web と同じ */
    .hud { position: absolute; top: 16px; left: 20px;
           font: bold 28px sans-serif; color: #fff;
           text-shadow: 0 2px 6px rgba(0,0,0,.6); }
  </style>
</head>
<body>
  <!-- data-m-text="名前" = その名前で C++ が送った値をここに表示 -->
  <div class="hud">SCORE <span data-m-text="view.hud.score">0</span></div>

  <!-- エンジン付属の 2 行（おまじない。毎回そのまま）-->
  <script src="mitiru_runtime/mitiru_cef_state.js"></script>
  <script src="mitiru_runtime/mitiru_bind.js"></script>
</body>
</html>

<span data-m-text="view.hud.score">0</span> が肝です。「この要素の中身に、view.hud.score という名前で届いた値を入れて」という印で、中の 0 は、まだ値が来ていないときに見えるフォールバックです。

C++ から値を送る

送るのは update の中です。Step 3 から update(Input in, Hud hud, float dt) の形にしてあるので、中で hud.set(...) を呼ぶだけ。src/main.cpp の update にこの 1 行を足します:

void update(Input in, Hud hud, float dt) {
    // …これまでの中身（プレイヤーを動かす・落下物・当たり判定）はそのまま…

    hud.set("view.hud.score", score);          // ← この 1 行。scene.html の同じ名前へ届く
}

場所は update の中ならどこでも OK（毎フレーム送られます）。名前 "view.hud.score" は、scene.html の data-m-text="view.hud.score" と完全に一致させてください — これが C++ と画面をつなぐ唯一の約束です。あとは要らなくなった s.text("SCORE …") を draw から消せば、表示が HTML の HUD に切り替わります。

これだけです。C++ は hud.set("名前", 値) で送る、HTML は data-m-text="名前" で受ける — つなぎの JavaScript は 1 行も要りません。あとは CSS を盛れば、影・角丸・グラデ・アニメ付きの HUD になります。「GAME OVER」をフェードインのモーダルにするのも、ボタンで Restart するのも同じ要領です。
