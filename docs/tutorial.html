TUTORIAL

はじめてのゲーム

C++ だけで小さなゲーム「スター・キャッチ」を作る。下のプレイヤーを左右に動かし、落ちてくる星を受け止めるとスコアが増える — それだけのゲームだ。並べる順番はコードの構造順ではなく、実際に組み立てる順にした。まず四角を一個動かし、ゲームの形にして、絵を入れ、数字を詰め、詰まったら窓を開ける。ホットリロードも観察窓も、その手が要る場面になって初めて出てくる。

作るもの

完成形がこれ。プレイヤー・星・爆弾はスプライト（画像）、背景は draw のグラデーション、左上の SCORE は s.text。描画はすべて C++ で、外部のシーンエディタは使っていない。星を取ると +SCORE、混ざった爆弾を取ると GAME OVER、Space で再開する。

ここで作るのは mitiru new my-catch で生成される自分のプロジェクトで、同梱サンプルを動かすのではない。コードは一度に貼らず、動く最小から少しずつ太らせていく。完成した全文は最後に置いた。

まず四角を一個、動かす

いきなり全部は書かない。最初に欲しいのは「キー入力でプレイヤーが左右に動く」という手応えだけだ。絵もスコアも後回しでいい。

mitiru new my-catch
cd my-catch

書き換えるのは src/main.cpp 一つ。動く最小はこれだけだ:

#include <mitiru/module/Game.hpp>
using namespace mitiru;

struct CatchGame {
    float playerX = 640;                       // プレイヤーの左右位置（中心）

    void update(Input in, Hud hud, float dt) {
        playerX += in.move().x * 600.0f * dt;   // 左右に動かす
    }
    void draw(Screen& s) {
        // まだ絵がないので、四角をプレイヤーに見立てて置く
        s.drawRect(playerX - 48, 548, 96, 130, sgc::Colorf{0.9f, 0.3f, 0.7f, 1.0f});
    }
};
MITIRU_GAME(CatchGame)   // この struct をゲームの入口にする
mitiru run

窓が開いて、紫の四角が矢印キーで左右に動く。これがプロトタイプだ。

入力の読み方。 in.move() は移動入力を一つにまとめて返す（.x .y は各 −1〜1）。矢印キー・WASD・ゲームパッドの左スティックが、すべてこの一つに合流する。だから playerX += in.move().x * 600 * dt と書くだけで、どの入力でも左右に動く。速度の 600 はいったん直書きでいい — あとで触りやすい場所に出す。update の引数 hud は今は使わないが、観察窓を開くときに効いてくる。

ゲームは src/main.cpp 一つに書いている。このゲームは小さいのでそれで足りるが、大きくなれば敵や弾は別ファイルの class に分けていく。一つの struct に押し込め続ける必要はない。ただし「いちばん外側の状態（CatchGame）」だけは素直なまま保つ — その理由はあとで出てくる。

落ちてくる星を足して、ゲームにする

四角が動いたら、ゲームの形にする。上から物を落とし、プレイヤーと重なったらスコア、混ざった爆弾を取ったら終了。まず状態に「落ちてくる物」と「スコア」を足す。乱数 rng もメンバとして持っておく。

#include <algorithm>                    // std::clamp
#include <mitiru/core/Random.hpp>     // 乱数 mitiru::Random

// 落ちてくる物 1 個分。kind: 0=星(良) / 1=爆弾(悪)
struct Item { float x, y; int kind; bool alive; };

struct CatchGame {
    float  playerX = 640;
    Item   items[24] {};        // 落ちてくる物は最大 24 個（全部 alive=false で開始）
    int    score = 0;
    bool   over = false;
    float  spawnIn = 0.0f;        // 次の落下物を出すまでの残り秒
    float  happyTimer = 0.0f;     // 星を取った直後、喜び表情を出す残り秒
    Random rng{1234};            // 乱数（seed 固定 = リプレイ決定論）
    // update / draw はこの下
};

update に「出す・落とす・当たり判定」を足す:

void update(Input in, Hud hud, float dt) {
    if (over) {                                // ゲームオーバー中は決定キーで再開だけ
        if (in.confirmPressed()) { *this = CatchGame{}; }
        return;
    }
    if (happyTimer > 0) happyTimer -= dt;

    playerX += in.move().x * 600.0f * dt;            // 左右に動かす
    playerX = std::clamp(playerX, 48.0f, 1232.0f);   // 画面外に出ない

    spawnIn -= dt;                                   // 0.6 秒ごとに 1 個出す
    if (spawnIn <= 0) {
        spawnIn = 0.6f;
        for (Item& it : items)
            if (!it.alive) {
                it.alive = true;
                it.x = rng.nextFloat(60, 1220);          // 出る x をランダムに
                it.y = -40;
                it.kind = rng.nextBool(0.12f) ? 1 : 0;   // 12% で爆弾
                break;
            }
    }

    sgc::Rectf player{playerX - 46, 568, 92, 84};   // 判定枠 {x, y, 幅, 高さ}
    for (Item& it : items) {
        if (!it.alive) continue;
        it.y += 300.0f * dt;                              // 下へ落とす
        sgc::Rectf box{it.x - 28, it.y - 28, 56, 56};
        if (player.intersects(box)) {                     // 重なった = キャッチ
            if (it.kind == 1) over = true;                  // 爆弾 → ゲームオーバー
            else { score += 1; happyTimer = 0.35f; }        // 星 → +1 して喜ぶ
            it.alive = false;
        } else if (it.y > 760) it.alive = false;        // 下に抜けたら消す
    }
}

当たり判定はエンジンが持っている。 sgc::Rectf（{x, y, 幅, 高さ}）どうしが重なったかは .intersects() で一発。点が矩形に入っているかは .contains()。ここでは「プレイヤーの判定枠」と「落下物の枠」が重なったらキャッチとし、星なら score、爆弾なら over にしている。やり直しは *this = CatchGame{};（状態をまるごと初期値へ）の 1 行で済む。

draw 側も、星はまだ四角で仮置きしておく。絵はこの次で入れる:

void draw(Screen& s) {
    for (Item& it : items)
        if (it.alive)
            s.drawRect(it.x - 12, it.y - 12, 24, 24,
                       it.kind == 1 ? sgc::Colorf{0.9f,0.2f,0.2f,1} : sgc::Colorf{1,0.85f,0.2f,1});
    s.drawRect(playerX - 48, 548, 96, 130, sgc::Colorf{0.9f, 0.3f, 0.7f, 1.0f});
    s.text("SCORE " + std::to_string(score), 24, 20, color::White, 24);
}

もう遊べる。紫の四角を動かして、黄色い四角（星のつもり）を受け、たまに混ざる赤い四角（爆弾）を避ける。手触りはまだ素っ気ないが、ルールは動いている。

絵を入れる前に、画像を用意する

絵を入れる前に、画像を 4 枚そろえる。下のをそのまま使っていい。クリックで保存して、プロジェクトの assets/sprites/ に同じ名前（player.png / player_happy.png / star.png / bomb.png）で置く。自分で描き替えても、名前さえ合えば動く。

すべて透過 PNG（背景が透けるので、重ねても四角い縁が出ない）。

絵を入れる — 四角を画像に

手応えが分かったら、四角を絵に差し替える。やることは draw の drawRect を sprite に変えるだけだ。

void draw(Screen& s) {
    // 背景: 上→下のグラデーション
    s.drawGradientRect(sgc::Rectf{0, 0, 1280, 720},
                       sgc::Colorf{0.28f,0.34f,0.56f,1}, sgc::Colorf{0.80f,0.74f,0.86f,1});

    // 落下物（星 / 爆弾）。id で画像を指定。56px なので中心から 28 引いた所を左上に
    for (Item& it : items)
        if (it.alive) s.sprite(it.kind == 1 ? "bomb" : "star", it.x - 28, it.y - 28);

    // プレイヤー（96×130）。星を取った直後だけ喜び表情に切り替える
    const char* who = (happyTimer > 0) ? "player_happy" : "player";
    s.sprite(who, playerX - 48, 548);

    s.text("SCORE " + std::to_string(score), 24, 20, color::White, 24);
}

s.sprite("id", x, y) の "id" は画像ファイルの名前だ。エンジンはゲームの隣の assets/sprites/<id>.png を探して描く。"player" なら player.png。絵を増やすのは、PNG を置いて名前を渡すだけ。中心を (x, y) に置きたいときは幅の半分を引いて左上に渡す（96px のプレイヤーなら -48、56px の星なら -28）。表情の切り替えも「どの id を描くか」を変えるだけで、新しい状態は要らない。

ここで一度 mitiru run を止めて、mitiru watch で起動し直しておく。すると src/ を保存した瞬間、ゲームを止めずに新しいコードへ差し替わる — これがホットリロードだ。watch で走らせたまま draw の drawRect を sprite に書き換えて保存すると、動いている四角がその場で絵に変わる。画像ファイル自体を別の絵に差し替えて保存しても同じで、その場合はビルドすら要らない。

数字を詰める — ホットリロードが効くところ

絵が入ると、今度は速さや落下が気になってくる。プレイヤーが鈍い、星が速すぎる、背景の色が違う。こういう「何度も値を変えて確かめる」作業こそ、ホットリロードの本領だ。

まず、コードに散らばった数字を、触りやすいようファイルの先頭に名前付きで出す。update / draw の中の 600 や 300、背景色のリテラルを、この名前に置き換える:

// ── チューニング: ここを書き換えて保存するとホットリロードで即反映 ──
constexpr float       kPlayerSpeed = 600.0f;                   // プレイヤーの左右速度
constexpr float       kFallSpeed   = 300.0f;                   // 落下スピード
constexpr sgc::Colorf kBgTop   {0.28f, 0.34f, 0.56f, 1.0f};    // 背景グラデ 上
constexpr sgc::Colorf kBgBottom{0.80f, 0.74f, 0.86f, 1.0f};    // 背景グラデ 下

あとは mitiru watch で走らせたまま、上から書き換えて保存するだけ。ゲームは落ちず、スコアも保ったまま、手応えだけが変わる:

  • kPlayerSpeed 600 → 1400 … プレイヤーがきびきび動く
  • kFallSpeed 300 → 820 … 星が速く落ちて難しくなる
  • kBgTop / kBgBottom の色を変える … 背景が夕焼けに変わる

書き間違えてビルドが壊れても問題ない。エラーが画面に帯で出て、ゲームは前のコードのまま動き続ける。直して保存すれば戻るので、コンソールと往復しなくていい。

詰まったら、窓を開く

画面を見ても分からないことがある。スコアが思ったように増えない、ある値がじわじわずれていく — 数字が画面に出ていないと、原因が見えない。そういうとき、状態をそのまま映す窓を開く。

開き方はコードに一行。update に渡ってくる hud に「この窓を開いて」と頼むだけだ:

void update(Input in, Hud hud, float dt) {
    hud.open(Tool::Inspector);   // 状態を見る窓を開く
    // …いつもの update…
}

同じ窓は一度しか開かない（毎フレーム呼んでもエンジンが重複を弾く）。CLI でツールを起動するのではなく、どの窓を見たいかがコードに残る。開いた窓には struct のフィールド（playerX・score・frame…）がそのまま並び、ゲームの隣でライブに動く。

窓に並ぶフィールドは MITIRU_REFLECT(CatchGame, playerX, score, …) の一行で申告する。自分で計算した途中の値を見たいときは hud.watch("game", "Catch", "…") で名前を付けて送れば、同じ窓に出る。値の履歴グラフまで欲しければ、入口を MITIRU_GAME から MITIRU_GAME_SERIES に変えるだけ（全文はその形にしてある）。

inspector のほかにも、入力の生値・過去フレームへの巻き戻し・録画再生・fps 計測・音量メーターの窓があり、どれも hud.open(Tool::…) の Tool:: を変えれば開く。巨大なエディタは開かない。一つの窓は一つの関心事だけを映す — これが MitiruEngine の流儀だ。それぞれの窓と、AI にゲームの全状態を読ませる AI Lens は、機能リファレンスのデバッグ窓・AI Lens の章にまとめてある。

なぜ、これが全部できるのか

ホットリロードで状態が消えないのも、窓に状態がそのまま映るのも、録画したプレイを完全再現できるのも、出どころは一つだ — ゲームの状態を一個の struct にまとめ、それをエンジンが預かっている。

エンジンはこの struct をまるごとコピーして保存・復元する。だから新しいコードへ状態をそのまま渡せるし、毎フレームの状態を記録して巻き戻せるし、AI に全状態を読ませられる。これが成り立つには、状態が「ただのデータ」であってほしい — 仮想関数やポインタを持たず、コピーで完結する素直な型（flat POD）。CatchGame をその形に保っているのはそのためだ。絵をゲームが持たず id で参照するだけ、という Step もここに効いている。テクスチャはエンジン側がまとめて持ち、ゲームは "player" という文字列を渡すだけなので、struct は重い物を抱えず素直なまま保てる。

これはいちばん外側の状態だけの話だ。中で使う敵や弾は普通に class で書いていい。トップの状態だけ素直に保つ、という住み分けである。

「何が反映されて、何が残るか」も、ここから決まる。値がコードに焼き込まれるものか、実行中の状態かで、3 つに分かれる:

反映される
code		constexpr の定数（kPlayerSpeed など）・update / draw のロジック・スプライトの画像。新しい DLL のコードや絵に焼き込まれて丸ごと入れ替わるので、保存するたびに即反映される。この章でやってきたのは全部これ。
残る
state		struct のいまの値（score・playerX・落下物の位置）。状態は預かったまま新しいコードへ渡るので、走行中の値はそのまま残る。だから初期値 playerX = 640 を 100 に書き換えても、走っているプレイヤーは動かない（再起動して初めて効く）。
壊れる
layout		struct にフィールドを足す・消す・並べ替える・型を変える。状態の形が変わると、預かっていたデータが新しい形に合わず壊れる（＝リセット）。形を変えるときは再起動が安全。
使い分け: 数値や条件の調整は止めずに何度でも。状態の形（struct のフィールド）を変えたときだけ再起動。このループ全体を、状態を一つの struct にまとめてエンジンに預ける形（MITIRU_GAME）が支えている。

見た目を HTML / CSS にする

いまスコアは s.text(...) で C++ から直接描いている。これを HTML と CSS の HUD に置き換えられる。ゲームのルール（C++）はそのまま、見た目だけを Web の書き方で作り直せる。

mitiru new で作ったプロジェクトはこうなっている。ロジックは src/main.cpp（C++）、画面は assets/scene.html（HTML / CSS）、絵は assets/sprites/（PNG）— 触るのはこのあたりだけだ:

my-catch/
├─ mitiru.toml          # 設定（ウィンドウサイズなど）
├─ src/
│  └─ main.cpp          # ← ゲームのロジック（C++）
└─ assets/
   ├─ scene.html        # ← 画面（HTML/CSS）。HUD の入口
   └─ sprites/          # ← スプライト（PNG）。s.sprite("id") の id に対応
      ├─ player.png
      ├─ player_happy.png
      ├─ star.png
      └─ bomb.png

エンジンはゲーム起動時に assets/scene.html を読み込み、ゲーム画面の上に透明なオーバーレイとして重ねる。だから C++ が描いた絵（背景・星・プレイヤー）の上に、HTML の HUD が乗る。scene.html は普通の HTML で、CSS は <style> の中に書く。末尾の <script> 2 行はエンジン付属の部品で、mitiru build が mitiru_runtime/ を隣に自動コピーするので、この 2 行をそのまま書く:

<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <style>
    /* CSS はここ。影・角丸・色、Web と同じ */
    .hud { position: absolute; top: 16px; left: 20px;
           font: bold 28px sans-serif; color: #fff;
           text-shadow: 0 2px 6px rgba(0,0,0,.6); }
  </style>
</head>
<body>
  <!-- data-m-text="名前" = その名前で C++ が送った値をここに表示 -->
  <div class="hud">SCORE <span data-m-text="view.hud.score">0</span></div>

  <!-- エンジン付属の 2 行（毎回そのまま）-->
  <script src="mitiru_runtime/mitiru_cef_state.js"></script>
  <script src="mitiru_runtime/mitiru_bind.js"></script>
</body>
</html>

肝は <span data-m-text="view.hud.score">0</span>。「この要素の中身に、view.hud.score という名前で届いた値を入れて」という印で、中の 0 はまだ値が来ていないときに見えるフォールバックだ。送るのは update の中、hud.set(...) 一行:

void update(Input in, Hud hud, float dt) {
    // …これまでの中身はそのまま…
    hud.set("view.hud.score", score);   // scene.html の同じ名前へ届く
}

名前 "view.hud.score" は、scene.html の data-m-text="view.hud.score" と完全に一致させる — これが C++ と画面をつなぐ唯一の約束だ。あとは要らなくなった s.text("SCORE …") を draw から消せば、表示が HTML の HUD に切り替わる。C++ は hud.set("名前", 値) で送る、HTML は data-m-text="名前" で受ける — つなぎの JavaScript は一行も要らない。あとは CSS を盛れば、影・角丸・グラデ・アニメ付きの HUD になる。

全コード

ここまでを一つにまとめた、そのまま遊べる src/main.cpp の全文。assets/sprites/ に 4 つの PNG を置いて mitiru run。長いので折りたたんである。入口は MITIRU_GAME_SERIES（履歴グラフ付き）にし、観察窓に出すフィールドを MITIRU_REFLECT で申告した形にしてある。

src/main.cpp の全文 
// catch — スター・キャッチ

#include <algorithm>
#include <cstdint>
#include <cstdio>
#include <string>

#include <mitiru/core/Random.hpp>
#include <mitiru/module/Game.hpp>

using namespace mitiru;

// ── チューニング: ここを書き換えて保存するとホットリロードで即反映 ──
constexpr float       kPlayerSpeed = 600.0f;                   // プレイヤーの左右速度
constexpr float       kFallSpeed   = 300.0f;                   // 落下スピード
constexpr sgc::Colorf kBgTop   {0.28f, 0.34f, 0.56f, 1.0f};    // 背景グラデ 上
constexpr sgc::Colorf kBgBottom{0.80f, 0.74f, 0.86f, 1.0f};    // 背景グラデ 下

// ── 画面と大きさ ──
constexpr float kScreenW  = 1280.0f;
constexpr float kScreenH  = 720.0f;
constexpr float kPlayerFeetY = 678.0f; // プレイヤーの足元の y
constexpr float kPlayerW   = 96.0f;
constexpr float kPlayerH   = 130.0f;
constexpr float kItemR     = 28.0f;    // 落下物スプライト (56px) の半径
constexpr int   kMaxItems = 24;

// 落ちてくる物 1 個 (flat POD)。kind: 0=星(良) / 1=爆弾(悪)。
struct Item { float x, y; int kind; bool alive; };

// ── ゲームの状態 (flat POD — ポインタ・vector・string を持たない) ──
struct CatchGame
{
    float         playerX = kScreenW * 0.5f;
    Item          items[kMaxItems] {};
    int           score   = 0;
    bool          over    = false;
    float         spawnIn = 0.0f;
    float         happyTimer = 0.0f;
    std::uint32_t frame   = 0;                // 経過フレーム (履歴グラフの横軸)
    bool          opened  = false;
    Random        rng{1234};                  // seed 固定でリプレイ決定論

    void update(Input in, Hud hud, float dt)
    {
        if (!opened) { hud.open(Tool::Inspector); opened = true; }   // 観察窓を 1 回だけ開く

        if (over)
        {
            if (in.confirmPressed()) { CatchGame fresh{}; fresh.opened = opened; *this = fresh; }
            return;
        }

        if (happyTimer > 0.0f) { happyTimer -= dt; }
        ++frame;

        playerX += in.move().x * kPlayerSpeed * dt;
        playerX = std::clamp(playerX, kPlayerW * 0.5f, kScreenW - kPlayerW * 0.5f);

        spawnIn -= dt;
        if (spawnIn <= 0.0f)
        {
            spawnIn = 0.6f;
            for (Item& it : items)
                if (!it.alive)
                {
                    it.alive = true;
                    it.x     = rng.nextFloat(60.0f, kScreenW - 60.0f);
                    it.y     = -40.0f;
                    it.kind  = rng.nextBool(0.12f) ? 1 : 0;
                    break;
                }
        }

        const sgc::Rectf player{playerX - 46.0f, kPlayerFeetY - 110.0f, 92.0f, 84.0f};
        for (Item& it : items)
        {
            if (!it.alive) { continue; }
            it.y += kFallSpeed * dt;
            const sgc::Rectf box{it.x - kItemR, it.y - kItemR, kItemR * 2.0f, kItemR * 2.0f};
            if (player.intersects(box))
            {
                if (it.kind == 1) { over = true; }
                else { score += 1; happyTimer = 0.35f; }
                it.alive = false;
                continue;
            }
            if (it.y > kScreenH + 40.0f) { it.alive = false; }
        }

        // 観察窓へ送る (開いている時だけ映る)
        char json[96];
        std::snprintf(json, sizeof(json), "{\"score\":%d,\"playerX\":%d}", score, static_cast<int>(playerX));
        hud.watch("catch", "Catch", json);
    }

    void draw(Screen& s)
    {
        s.drawGradientRect(sgc::Rectf{0.0f, 0.0f, kScreenW, kScreenH}, kBgTop, kBgBottom);

        for (const Item& it : items)
            if (it.alive)
                s.sprite(it.kind == 1 ? "bomb" : "star", it.x - kItemR, it.y - kItemR);

        const char* who = (happyTimer > 0.0f) ? "player_happy" : "player";
        s.sprite(who, playerX - kPlayerW * 0.5f, kPlayerFeetY - kPlayerH);

        s.text("SCORE " + std::to_string(score), 24, 20, color::White, 24);

        if (over)
        {
            const float goW = s.measureText("GAME OVER", 44.0f).x;
            s.text("GAME OVER", (kScreenW - goW) * 0.5f, 312.0f, color::White, 44);
            const float subW = s.measureText("press SPACE to retry", 20.0f).x;
            s.text("press SPACE to retry", (kScreenW - subW) * 0.5f, 376.0f, color::Gray, 20);
        }
    }
};

// GameMemory から値を 1 つ引く関数 (DLL 境界を渡せる double(*)(const void*))。
double scoreProbe(const void* m)   { return static_cast<const CatchGame*>(m)->score; }
double playerXProbe(const void* m) { return static_cast<const CatchGame*>(m)->playerX; }

// 観察窓に出す GameMemory のスカラ場
MITIRU_REFLECT(CatchGame, playerX, score, over, frame, spawnIn, happyTimer);

// 入口 + 履歴グラフ。host が CatchGame を 1 個作り update/draw を回し、score / X の履歴を自動生成する。
MITIRU_GAME_SERIES(CatchGame,
    { "score", "Score",    &scoreProbe,   0.0, 0 },
    { "x",     "Player X", &playerXProbe, 0.0, 0 });

道具箱

ゲームを書くとき触るのは、主に 3 つのオブジェクトだけだ。update(Input in, Hud hud, float dt) の in と hud、そして draw(Screen& s) の s。よく使うものを並べておく。一覧を一度に覚える必要はなく、必要になったときに引けばいい。

in — 入力を読む（Input）

in.move()移動入力を 1 つに合成（矢印 / WASD / 左スティック）。.x .y 各 −1〜1。x += in.move().x * speed * dt
in.confirmPressed()「決定」を押した瞬間（Space / Z / Enter / パッド A）。再開・メニュー送りなど
in.down(Key::Left)キーが押されている間ずっと true（個別キーが要るとき）
in.pressed(Key::Space)押した瞬間だけ true / in.released(Key::Z) は離した瞬間
in.mouseDown(0) / mouseX() / mouseY()マウスのボタンと座標（0=左 1=右 2=中）
in.padDown(Pad::A) / leftStick()ゲームパッド（つながっていれば自動で使える）

hud — 送る・鳴らす・演出・窓（Hud）

hud.set("view.hud.score", score)HTML の表示へ値を送る（data-m-text が受ける）
hud.play("hit")効果音を鳴らす（hud.play("hit", 0.6f) で音量指定）
hud.flash(color::White)画面を一瞬フラッシュ（被弾演出など）
hud.screenshot()その瞬間の画面を画像保存。if (over) hud.screenshot(); でゲームオーバーだけ自動保存
hud.open(Tool::Inspector)独立ウィンドウを開く（何度呼んでも 1 回だけ開く）
hud.watch("game", "Catch", json)観察窓に好きな値を送る
hud.quit()ゲームを終了する

s — 画面に描く（Screen）

s.sprite("player", x, y)画像を描く。id は assets/sprites/<id>.png。(x, y) は左上。s.sprite(id, x, y, scale) で拡大縮小
s.drawRect(x, y, w, h, color)四角を描く（色は sgc::Colorf{r,g,b,a} か color::Red）。drawRectCentered は中心指定版
s.drawGradientRect(rect, top, bottom)上→下のグラデーション矩形（背景に）
s.measureText("文字", 44)描いたときの文字の幅・高さを返す。(1280 - w)/2 で中央寄せ
s.text("SCORE", x, y, color::White, 24)文字を描く
