CLI

コマンドリファレンス

MitiruEngine の入口は mitiru コマンドです。エディタの巨大なメニューの代わりに、1 コマンド 1 つの仕事に絞った 23 個のコマンドだけがあります。作る・動かす・確かめる・配る ── やりたいことの数だけコマンドがあり、それ以上はありません。

全コマンド一覧

引数なしの mitiru は対話ランチャー（menu と同じ）になります。各コマンドは mitiru <コマンド> --help で詳しいフラグを確認できます。

newテンプレートから新しいプロジェクトを作る
buildいまのプロジェクトをビルドする
runビルドして実行する
watchsrc/ の変更を監視してホットリロード
debugDebug 構成 + デバッグ補助を有効にして実行
uiHTML/CSS の UI をビルドなしでブラウザ即プレビュー
lintscene.html の data-m-* と C++ が送る値を静的に突き合わせ
verifyヘッドレスでビルド・起動・スクリーンショット → 合否を JSON で出力
replay入力リプレイの記録・再生・回帰テスト（同じ入力なら同じ結果）
mcpMCP サーバーを起動して AI ツールにゲームを観測・操作させる
inspect実行中のゲームに別ウィンドウの inspector を後付けする
rendererレンダラだけを単独起動
input入力サブシステムだけを単独起動
sceneシーン管理だけを単独起動
audioオーディオミキサーだけを単独起動
dist配布フォルダを組み上げる
doctor前提ツールが揃っているか診断

installまっさらなマシンを一括セットアップ

つくる・動かす

mitiru new — プロジェクトを作る

テンプレートから新しいプロジェクトを 1 フォルダ作ります。テンプレートは hello（最小）・clicker（クリッカー）・shooter（縦シューティング）の 3 種。生成されるゲームは DLL としてビルドされ、mitiru_host ランチャーから起動されます。

mitiru new myGame              # ./myGame/ を hello テンプレートから作成
mitiru new myGame -t clicker   # clicker テンプレートから開始
mitiru new myGame --force      # 既存フォルダを上書き

mitiru build — ビルドする

カレント（または親）ディレクトリの mitiru.toml を見つけ、指定版のエンジンソースを ~/.mitiru/cache/ に取得し、CMake の configure + build を実行します。ビルドだけが仕事で、実行はしません。

mitiru build             # Debug ビルド (既定)
mitiru build --release   # Release ビルド

mitiru run — 実行する

ビルドしてからプロジェクトを起動します。--inspect でゲームと並走するツールウィンドウを 1 枚開けます（ゲーム終了とともに閉じます）。--record でその回の入力を入力記録ファイル（.mtrr）に保存すれば、あとで mitiru replay --test --game の回帰テストに使えます。

mitiru run                        # ビルドして起動
mitiru run --inspect              # gameplay inspector を並走
mitiru run --inspect timetravel   # 巻き戻し窓 (perf / inspector / timetravel
                                  #   / mixer / scene / replay / input から選択)
mitiru run --console              # ブラウザに実行時コントロールパネルを開く
mitiru run --record session.mtrr  # 入力を記録 (replay --test --game 用)

mitiru watch — ホットリロードで開発する

一度ビルドして起動したあと、src/ の変更のたびに再ビルドします。ホストは新しい DLL を検知してその場で差し替え、ゲームの状態は差し替え後も生き残ります。assets/ の HTML / CSS / JS はエンジン側のホットリロードが拾います。Ctrl-C で監視終了（ゲームウィンドウも閉じます）。

mitiru watch                      # 保存するたび、動いたまま反映
mitiru watch --inspect timetravel # ツール窓も並走できる

mitiru debug — デバッグ補助つきで実行する

mitiru run の Debug 特化版です。構成を Debug に固定し、環境変数 MITIRU_DEBUG=1 / MITIRU_INSPECTOR=1 を立てて起動します。

mitiru debug

mitiru ui — UI をビルドなしでプレビューする

C++ のビルドを一切せずに、assets/ をローカル HTTP サーバーで配信してシーンをブラウザで開きます。window.mitiru ブリッジはモック実装が立つので、mitiru_bind.js の data-m-* バインドはエンジンなしでそのまま動きます。HTML / CSS だけを高速に往復したいときの専用コマンドです。

mitiru ui                     # assets/scene.html を :8137 で配信
mitiru ui assets/hud.html     # 特定のシーンを指定
mitiru ui --state mock.json   # {"view.hp": 80} のような JSON で状態を注入
mitiru ui --port 9000         # ポート変更

mitiru lint — バインドのズレを静的に検出する

scene.html の data-m-* と C++ 側が送る値を突き合わせ、C++ と HTML の境目で黙って失敗するもの（C++ が一度も送らない名前、壊れたマークアップ、値を画面へ流し込むエンジン付属スクリプトの読み込み漏れなど）を実行前に検出します。既定は警告のみで、CI 用に --strict があります。

mitiru lint            # 警告を表示
mitiru lint --strict   # 検出があれば非ゼロ終了 (CI 向け)

確かめる

mitiru verify — ヘッドレスで合否を出す

ビルド → MITIRU_AI=1 で起動 → 指定フレーム待機 → スクリーンショット取得 → 終了、までを人手なしで実行し、結果を 1 つの JSON で stdout に出力します。終了コードは 0=合格 / 1=不合格 / 2=ビルドエラー。golden 画像（正解として保存した基準画像）との比較やリプレイ再生後の検証もできます。

mitiru verify                        # ビルド + スモークテスト
mitiru verify --golden ref.png       # golden 画像と比較 (既定閾値 95%)
mitiru verify --replay session.mtrr  # リプレイ再生後にスクリーンショット
mitiru verify --frames 600 --json    # 10 秒待機、JSON を整形出力

mitiru replay — 記録・再生・回帰テスト

同じ入力なら同じ結果になるリプレイの専用コマンドです。記録した入力ストリームはセッションをビットまで同一に再現します。--record / --replay / --test のどれか 1 つを指定します。--test --game は窓も CEF も出さずにこのプロジェクトのゲームを回し、最終状態の JSON を出力する ── そのまま回帰テストになります（記録は mitiru run --record で）。

mitiru replay --record demo.mtrr            # 記録 (デモ用サブシステム)
mitiru replay --replay demo.mtrr            # 再生
mitiru replay --test session.mtrr --game    # このゲームをヘッドレス回帰テスト
mitiru replay --test s.mtrr --expect e.json # 既知の最終状態と差分比較

mitiru mcp — AI ツールにゲームを触らせる

stdio で MCP（Model Context Protocol）を話すサーバーを起動します。Claude Code などの AI ツールから、状態取得（game_state / state_diff）・スクリーンショット・入力送信・ポーズ / 1 フレーム実行・タイムスケール変更・シーンツリー取得・verify 実行ができます。ゲーム側は MITIRU_AI=1 で起動しておきます（ポート既定 8090、--port か MITIRU_AI_PORT で変更）。

# Claude Code の .mcp.json に追加
{"mcpServers":{"mitiru":{"command":"mitiru","args":["mcp"]}}}

mitiru inspect — 実行中のゲームを後から覗く

動いているゲームのプロセスに、別の OS ウィンドウとして inspector を後付けします。ゲームはゲームの窓のまま、観測窓は別モニタにでも置けます。pid 省略時は直近のゲームを自動検出。--all で gameplay / input / timetravel の 3 窓を並べて開けます。

mitiru inspect                              # 直近のゲームを自動検出して接続
mitiru inspect 12345                        # pid 指定
mitiru inspect 12345 --inspectable timetravel  # 窓を 1 種だけ指定
mitiru inspect 12345 --all                  # 3 つの観測窓を並べて開く

サブシステム単独起動

エンジンの各サブシステムは、ゲームロジックなしで 1 個ずつ単独起動できます。「壊れているのはレンダラか、ゲームか」を切り分けたいとき、対象だけを起動して確かめられます。

mitiru renderer — レンダラだけ

描画パイプラインだけを起動し、グリッドとアニメーションするテストパターンを表示します。シェーダやパイプラインの調整、描画系の切り分けに使います。

mitiru renderer

mitiru input — 入力だけ

キーボード・マウスを捕捉し、エンジンが毎フレーム見ている入力（1 フレーム分をまとめたもの）をそのまま可視化します。レンダラもシーン管理も動きません。

mitiru input

mitiru scene — シーン管理だけ

シーンを重ねる・戻す・差し替えるときの遷移と、生成から破棄までの流れを、ゲームロジック抜きで観察します。

mitiru scene

mitiru audio — オーディオだけ

オーディオミキサーだけを初期化して起動します。.wav / .mp3 / .flac のパスを渡すと起動時に読み込みます。

mitiru audio
mitiru audio bgm.mp3   # 指定ファイルを読み込んで起動

配る・整える

mitiru dist — 配布フォルダを作る

Release ビルドして、ホスト・ランタイム・ゲーム DLL・アセット・ダブルクリック起動のランチャーをひとまとめにした、そのまま動く配布フォルダを組みます。詳しい構成と --pack（アセット梱包）は配布ページへ。

mitiru dist          # → dist/<名前>/ (無コンソールの <名前>.exe)
mitiru dist --zip    # zip も一緒に作る
mitiru dist --pack   # assets を 1 ファイルに埋め込んで隠す
mitiru dist --bat    # ログ確認用にコンソール表示の .bat も追加

mitiru doctor — 環境を診断する

OS・CMake・コンパイラなど、ビルドに必要な前提が揃っているかを確認し、足りないものには入手のヒントを出します。「動かない」と思ったら最初に実行するコマンドです。

mitiru doctor

mitiru clean — ビルド成果物を消す

プロジェクトの build/ を削除します。--all でエンジンソースのグローバルキャッシュ（~/.mitiru/cache/）も消し、次回ビルド時に再ダウンロードさせられます。

mitiru clean         # build/ を削除
mitiru clean --all   # エンジンキャッシュも削除

mitiru install — マシンを一括セットアップする

まっさらな Windows マシンに、MSVC Build Tools の導入（winget）・mitiru.exe の配置・PATH 追加・エンジンソースの事前キャッシュをまとめて行います。リリース zip 同梱の MitiruEngine_Installer.exe と同じ処理です。導入済みの項目は自動でスキップし、--force で修復インストールができます。

mitiru install            # 一括セットアップ (導入済みはスキップ)
mitiru install --dry-run  # 計画だけ表示、何も変更しない
mitiru install --force    # 修復インストール

mitiru update — エンジンの版数を上げる

公開リポジトリの最新リリースを調べ、mitiru.toml の engine 指定を更新します。マイナー以上の更新は互換性に影響しうるため、差分を表示して確認を取ってから適用します（コメントは保持され、engine の行だけ書き換わります）。

mitiru update           # 確認してから更新 + 事前取得
mitiru update --check   # 確認のみ、何も変更しない
mitiru update --yes     # 確認なしで適用 (自動化用)

mitiru self-update — CLI 自体を更新する

mitiru.exe そのものを最新リリースに差し替えます。プロジェクトが使うエンジンの版数は別の話なので、そちらは mitiru update です。

mitiru self-update           # 最新をダウンロードして差し替え
mitiru self-update --check   # 確認のみ

mitiru menu — 番号で選ぶ

コマンド名を覚えていなくても使える対話ランチャーです。いまの文脈（プロジェクトの中か外か）に応じた選択肢だけを表示し、番号で選んで実行します。引数なしの mitiru でも同じものが起動します（短縮形 mitiru m）。

mitiru        # 引数なしで対話ランチャー
mitiru menu   # 明示起動 (mitiru m でも可)

mitiru version — バージョンを表示する

CLI のバージョンとプラットフォームを表示します。

mitiru version
