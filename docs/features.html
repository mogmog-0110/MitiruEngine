FEATURES

MitiruEngine の機能と設計

MitiruEngine は、2D ゲームを中心に、HTML / CSS の画面表示、3D 描画、録画、巻き戻し、AI 連携まで扱う個人開発のゲームエンジンです。このページでは、実装した機能と、その実現方法をコードと実行画面で紹介します。

基本構成
update で状態を更新し、draw で描画します。
座標
左上が (0, 0)。標準画面は 1280 × 720 です。
状態管理
ゲーム状態を一括保存できる構成が、録画や巻き戻しにも使われます。

1. ゲームの基本構成

ゲームの状態を 1 つの struct に置き、毎フレームの更新と描画を分けます。最後の MITIRU_GAME が DLL の入口を生成します。

#include <mitiru.hpp>
using namespace mitiru;

struct MyGame {
    float x = 640;

    void init() { x = 640; }

    void update(Input in, float dt) {
        if (in.down(Key::Right)) x += 320 * dt;
    }

    void draw(Screen& s) {
        s.fillScreen(color::Black);
        s.drawRectCentered(x, 360, 48, 48, color::Cyan);
    }
};

MITIRU_GAME(MyGame)

init、update、draw は任意で、実装した関数だけが呼ばれます。update の引数も必要なものだけにできます。

update(Input in, float dt)入力と経過秒を使う
update(Input in, Hud hud, float dt)入力、音、HTML UI、各種機能を使う
update(float dt)経過秒だけを使う
draw(Screen& s)画面を描画する
エンジンはトップのゲーム状態を一括コピーし、ホットリロード、巻き戻し、録画に利用します。このためトップの struct は仮想関数やポインタを持たないデータとして定義し、可変長の要素には mitiru::FixedVec<T,N> を使います。条件は MITIRU_GAME がコンパイル時に確認します。敵や弾など、内部の部品は通常の class で実装できます。

2. 2D 図形

Screen に座標、寸法、色を渡して図形を描画します。

void draw(Screen& s) {
    s.fillScreen(hex(0x14182A));
    s.drawRect(40, 40, 120, 80, color::Red);
    s.drawRectCentered(640, 360, 100, 100, color::Blue);
    s.fillCircle(900, 200, 48, color::Yellow);
    s.line(0, 0, 1280, 720, color::White, 3);
}
drawRectFrame矩形の枠線
drawRoundedRect / drawRoundedRectFrame角丸矩形とその枠線
drawCircle / drawCircleFrame円とその枠線
drawEllipse / drawRing楕円とリング
drawArc / drawPie円弧と扇形。角度はラジアン
drawTriangle / drawPolygon三角形と凸多角形
drawRectRotated度数法で回転する矩形
drawGradientRect / H / 4縦、横、4 隅のグラデーション
drawRectPattern市松、ストライプ、ドット
drawDashedLine破線

矩形は Rect{x, y, 幅, 高さ}、2D 座標は Vec2{x, y} で表します。同じ Rect を当たり判定にも使います。

3. 色

色の型は mitiru::Color です。0〜255 の数値、16 進数、定義済みの名前から作成できます。

rgb(200, 0, 44)
rgba(255, 255, 0, 128)
hex(0xC8002C)
hexa(0xC8002C80)

color::White  color::Black  color::Gray   color::Red
color::Green  color::Blue   color::Yellow color::Orange
color::Cyan   color::Clear

Color c = color::Red; c.a = 0.3f; のように、.a を 0.0〜1.0 で指定すると透明度を変更できます。

フォント設定

C++ の描画で日本語を表示する場合は、mitiru.toml でフォントアトラスの収録範囲を選びます。

[font]
atlas = "japanese"  # latin / kana / japanese

latin は英数字、kana はかな、japanese はかなと常用漢字です。未指定または none ではフォントを読み込みません。HTML 側では font-family や @font-face を使えます。

setTrueTypeFontTTF の描画・計測コールバックを接続する
setSdfFontSDF の描画・計測コールバックを接続する
registerFont名前付きフォントを登録する
setFont登録済みフォントへ切り替える
ゲーム内のダメージ数値などは C++ で描画でき、スコアやメニューは HTML / CSS の HUD として構成できます。

5. 移動・回転・拡大

s.pushTransform(camX, camY);
drawScene(s);
s.popTransform();

s.pushRotation(angleRad, cx, cy);
s.drawRectCentered(cx, cy, 60, 60, color::Orange);
s.popTransform();

s.drawGroup({px, py}, spinDeg, [&](Screen& g) {
    g.drawRectCentered(0, 0, 40, 40, color::Cyan);
});

pushTransform(tx, ty, sx, sy) は平行移動と拡大縮小を適用します。変換は重ねられ、追加した回数と同じ回数だけ popTransform() を呼びます。pushRotation はラジアン、drawGroup の回転は度数法です。

6. 画像とスプライト

assets/sprites/hero.png は、拡張子を除いた ID で描画できます。

s.sprite("hero", x, y);
s.sprite("hero", x, y, 2.0f);

画像の読込結果はキャッシュされます。ファイルがない場合は初回だけ警告し、PNG を上書きすると実行中の画面へ約 0.5 秒で反映します。回転、切り出し、色の乗算には Texture を使い、読み込みは init() で 1 回だけ行います。

#include <mitiru/render/Texture.hpp>

struct MyGame {
    render::Texture tex;

    void init() {
        if (auto t =
            render::Texture::fromFile("player.png"))
            tex = std::move(*t);
    }

    void draw(Screen& s) {
        s.drawSprite(tex, {x, y, 64, 64});
        s.drawSprite(tex, {x, y, 64, 64}, color::Red);
        s.drawSprite(tex, {x, y, 64, 64},
            {32.0f * frame, 0, 32, 32},
            color::White, facingLeft);
    }
};

Texture::solid と Texture::checker は画像ファイルなしでテクスチャを生成します。drawPixelGrid は RGBA8 のバッファを描画し、自作ラスタライザや手続き生成に利用できます。

Texture はトップの状態へ直接置けません。画像はグローバルまたは別オブジェクトへ分け、ゲーム状態には座標やフレーム番号などの数値を残します。

7. 2D と組み合わせる 3D 描画

3D は 2D と同じ draw(Screen& s) の中で使います。camera3D と light3D を設定し、drawMesh で立方体、球、板を配置します。GPU の 3D レンダラーは MSAA とシャドウマップに対応し、2D の HUD を上へ重ねられます。

void draw(Screen& s) {
    s.clear(hex(0x111521));
    s.camera3D(
        {std::sin(t) * 13, 8.5f, std::cos(t) * 13},
        {0, 0.4f, 0}, 54);
    s.light3D({-0.5f, -1, -0.4f});

    s.drawMesh("cube", {0, -0.15f, 0},
        {14, 0.3f, 14}, {0, 0, 0}, hex(0x3A4250));
    s.drawMesh("cube", {0, 0.7f, 0},
        {1.4f, 1.4f, 1.4f}, {0, t * 60, 0}, hex(0xEA5535));
    s.drawMesh("sphere", {2.7f, 0.9f, 0},
        {1.2f, 1.2f, 1.2f}, {0, 0, 0}, hex(0x4C95F2));

    s.text("3D + 2D HUD", 28, 22, color::White, 28);
}

loadGltfMeshFromFile("model.gltf") で読み込んだメッシュも配置できます。大量のポリゴンや複雑なシェーダーを前提とする用途は対象外です。動作例と完全なコードは 3D のページ に掲載しています。

8. キーボードとマウス

down は押している間、pressed は押した瞬間、released は離した瞬間に真になります。

void update(Input in, float dt) {
    if (in.down(Key::Left)) x -= 320 * dt;
    if (in.pressed(Key::Space)) jump();
    if (in.released(Key::Z)) release();

    float mx = in.mouseX();
    float my = in.mouseY();
    if (in.mousePressed(0)) shootAt(mx, my);
}

Key::Left、Space、A…Z、F1…F12 などを指定できます。一覧にないキーには Windows 仮想キーコードの Key{0x..} を使います。マウスには mouseDown、mousePressed、mouseReleased があります。

HTML の操作は in.action("name")、値付きの操作は in.actionPayload("name") で受け取ります。詳細はHTML / CSS の画面と画面を作るに掲載しています。

9. ゲームパッドと操作割り当て

XInput と、DualShock 4 などの DirectInput 系に既定で対応します。機種にかかわらず同じ API で入力を取得できます。

void update(Input in, float dt) {
    if (!in.padConnected()) return;

    if (in.padPressed(Pad::A)) jump();
    Stick l = in.leftStick();
    x += l.x * 320 * dt;
    float rt = in.rightTrigger();
}

ボタンは Pad::Up/Down/Left/Right/Start/Back/A/B/X/Y/LB/RB/LStick/RStick、スティックは leftStick / rightStick、トリガーは leftTrigger / rightTrigger です。

enum class Act : uint8_t { Jump, Throw, Pause };

static constexpr Binding<Act> kMap[] = {
    { Act::Jump,
      { Key::Space, Key::W, Key::Up },
      { Pad::A } },
    { Act::Throw, { Key::X },
      { Pad::B, Pad::RB } },
    { Act::Pause, { Key::Enter },
      { Pad::Start } },
};

if (in.pressed(kMap, Act::Jump)) jump();
if (in.released(kMap, Act::Jump)) cutJump();

Binding の表で、1 つの操作へ複数のキーとパッド入力を割り当てられます。定番の操作には次の統合 API もあります。

if (in.confirmPressed()) advance();
if (in.cancelPressed()) back();
Stick m = in.move();
x += m.x * 320 * dt;

confirmPressed は Space、Z、Enter、パッドの A、Start、cancelPressed は Escape、パッドの B、Back をまとめます。move は矢印、WASD、十字キー、左スティックを -1〜1 の値へ統合します。

メニューは mitiru::MenuCursor を状態へ置き、updateVertical(in, 項目数, dt) で上下移動と長押しの反復を処理できます。操作の再割り当ては INPUT_REBIND_RECIPE.md にまとめています。

10. 再現可能な状態、録画、巻き戻し、AI 連携

mitiru::Random の種を in.rngSeed() から取得すると、同じ入力から同じ結果を再現できます。

Random rng(in.rngSeed());
int dmg = rng.nextInt(10, 50);
float angle = rng.nextFloat(0, 6.28f);
bool crit = rng.nextBool(0.15f);

ゲーム状態を一括して扱う

トップの struct には数値を中心とした状態を置きます。std::vector と std::string の代わりに FixedVec<T,N> と FixedString<N> を使用し、ポインタなどが混入すると MITIRU_GAME がコンパイルエラーにします。

入力と乱数の種を記録mitiru run --record と mitiru replay で同じプレイを再生し、回帰テストにも使う
毎フレームの状態を記録過去のフレームへ戻り、値が変化した時点を調べる
MITIRU_REFLECT状態を構造化 JSON として外部から読む

AI 用 API

公開するフィールドを宣言し、MITIRU_AI=1 mitiru run で起動すると、現在の状態、差分、別入力を与えた試行を API から取得できます。

MITIRU_REFLECT(MyGame, player, enemies, hp);
MITIRU_AI=1 mitiru run
GET /api/ai/state現在の全状態を構造化 JSON で返す
GET /api/ai/diffフレーム間の変更点を返す
POST /api/ai/branch現在の実行を変えず、別の入力を試す

構造体の配列では、要素の構造体を先に宣言します。ネストは 1 段、登録は 8 個まで、各マクロは最大 16 フィールドです。

MITIRU_REFLECT_STRUCT(Enemy, x, y, alive);
MITIRU_REFLECT(MyGame, player, enemies, hp);

詳細は AI ページの設計説明 に掲載しています。

巻き戻した地点へ修正を再適用する

直近 5 秒の状態と入力を常時保持します。問題が起きた時点へ戻り、C++ を修正して保存すると、ホットリロード後のコードへ同じ入力を再適用できます。操作手順をもう一度行わず、修正前後を同じ入力で確認できます。

11. 音声

音声ファイルは assets/audio/<id>.wav に置き、Hud から ID で再生します。

hud.play("hit");
hud.play("hit", 0.8f, 1.1f);
hud.music("bgm_field", true);
hud.music("bgm_boss", true, 1.0f, 0.5f);
hud.stopMusic(0.5f);

play は音量とピッチ、music はループ、音量、クロスフェード時間を指定できます。stopMusic はフェードアウト時間を受け取ります。

音声クロック

リズム判定には in.audioTime() の秒数を使います。戻り値が 0 の間は音声が未準備なので dt の積算で補います。非ゼロになった後は単調非減少で、録画再生でも同じ値を再現します。

double t = in.audioTime();
if (t > 0) judgeNote(t);

12. 演出、保存、時間制御

hud.flash(color, seconds)画面を指定色で一時的に覆う
hud.shake(seconds, pixels)画面を揺らす
hud.hitStop(seconds)指定時間だけ進行を止める
hud.fadeOut / fadeIn場面転換の暗転と復帰
hud.letterbox上下に黒帯を表示する
hud.save("slot0");
hud.load("slot0");

s.applyCamera(cam.x, cam.y, cam.zoom);
drawScene(s);
s.endCamera();

hud.screenshot();

セーブとロードには、巻き戻しや録画と同じ状態コピーを利用します。mitiru::Camera は位置と拡大率を保持し、endCamera より後の要素は画面へ固定できます。screenshot は現在の画面を画像として保存します。

方向を指定する画面揺れ

if (shake > 0)
    shake = std::max(0.0f, shake - dt * 2.6f);

float ox = std::sin(frame * 1.7f) * shake * 8.0f;
float oy = std::cos(frame * 2.3f) * shake * 8.0f;
s.drawRectCentered(px + ox, py + oy, 40, 40, color::White);

方向を指定する場合は、強度を状態として保持し、毎フレーム減衰させた値から描画位置をずらします。パーティクルは位置、速度、寿命を持つ矩形の固定長配列として更新し、寿命後は同じ枠を再利用できます。

Timer と Tween01

struct MyGame {
    mitiru::Timer spawnTimer;
    mitiru::Tween01 fadeIn;
};

if (spawnTimer.every(0.5f, dt)) spawn();
float a =
    fadeIn.step(1.2f, dt, mitiru::Ease::OutQuad);

Timer::every は超過時間を次回へ繰り越して周期実行します。一度だけの実行には once、初期化には reset を使います。補間は Linear、InQuad、OutQuad、InOutQuad、OutCubic、OutBack、OutBounce から選べます。カットシーンの構成例は EVENT_RECIPES.md に掲載しています。

13. HTML / CSS の画面

C++ から名前付きの値を送り、HTML の data-m-* 属性で受け取ります。この接続には JavaScript を必要としません。

hud.set("view.hud.score", score);
hud.set("view.boss.active", true);
<div class="hud">
  SCORE
  <span data-m-text="view.hud.score">0</span>
</div>
<div class="boss"
     data-m-show="view.boss.active">…</div>

ボタンは data-m-action="restart" とし、C++ では in.action("restart") で受け取ります。data-m-text、tpl、show、class、style、repeat の詳細は 画面を作る に掲載しています。

hud.watch("game", "Dodge", json) は観察データを Inspector へ送り、hud.runJs(code) は JavaScript を直接実行します。同梱の rewind などのサンプルと、mitiru new のひな型も C++ と HTML / CSS を組み合わせています。

状態履歴からグラフを生成する

MITIRU_GAME の代わりに MITIRU_GAME_SERIES を使い、状態から double を返す関数を登録すると、保存済みの各フレームへ関数を適用して系列を生成します。

double hpProbe(const void* m) {
    return static_cast<const MyGame*>(m)->hp;
}

MITIRU_GAME_SERIES(MyGame,
    { "hp", "HP", &hpProbe, 35.0, 1 });

例では HP が 35 を下回った箇所へマーカーを表示します。ゲーム側で履歴を重複して保存する必要はありません。

15. サブシステムの単独起動

描画、入力、シーン、音声を別々の実行ファイルとして起動できます。ゲームロジックと Chromium を読み込まず、対象の層だけを確認します。

mitiru renderer  # グリッドと往復する矩形
mitiru input     # 256 キー、マウス、押下履歴
mitiru scene     # 12 個のエンティティ
mitiru audio     # 440 Hz とレベルメーター
mitiru audio bgm.wav  # wav / mp3 / flac

配布 ZIP には mitiru_subsys_renderer.exe などが mitiru.exe と並んで入り、基本操作では ESC で終了します。各実行ファイルの構成は SUBSYSTEMS.md に掲載しています。

16. 当たり判定

moveAndCollide は、矩形の移動量をタイルとの衝突に合わせて修正し、位置と接触した面を返します。

auto r = mitiru::moveAndCollide(
    x, y, w, h, dx, dy, 16.0f,
    [&](int tx, int ty) {
        return map.solid(tx, ty);
    });

x = r.x;
y = r.y;
if (r.hitDown) onGround = true;
Rect player{playerX - 28, 660, 56, 24};
Rect block{b.x, b.y, 44, 44};

if (player.intersects(block)) over = true;
if (block.contains(Vec2{mx, my})) hit();

円同士は dx*dx + dy*dy <= (r1+r2)*(r1+r2) で判定し、平方根の計算を省けます。クリックは矩形の contains または円との距離で判定できます。

17. プロジェクト設定と配布

ウィンドウと HTML UI の設定は、プロジェクト直下の mitiru.toml に記述します。ひな型は mitiru new が生成します。

[project]
name = "my-game"
engine = "0.24.0"

[window]
width = 1280
height = 720
fixed_size = true

[cef]
enabled = false

engine は使用するエンジンの版で、mitiru update から更新します。[cef] enabled = false では HTML UI を無効にし、配布物から Chromium を除外できます。完成後は mitiru dist が実行可能な配布フォルダを生成します。詳細は 配布する に掲載しています。
