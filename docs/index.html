MitiruEngine

C++ でゲームを書くための、ふだん使いのエンジン

ヘッダだけで動く C++20 のゲームエンジン。ゲームのロジックは C++、UI まわりは HTML/CSS で組めます。

はじめての MitiruEngine → チュートリアル サンプル一覧

ゲームの中身は C++、画面まわりは HTML/CSS。ふだんの感覚で、C++ のゲームをつくれます。

3 分でわかる MitiruEngine

Hello World は 30 行ほど。エンジンを継承して update() と draw() を書き、engine.run() を呼ぶだけ。 画面はそのまま開きます。 

#include <mitiru/Mitiru.hpp>

class MyGame final : public mitiru::Game {
public:
  mitiru::Size layout(int w, int h) override { return {w, h}; }

  void update(float dt) override { m_t += dt; }

  void draw(mitiru::Screen& s) override {
    const float w = (float)s.width();
    const float h = (float)s.height();
    s.drawRect({0, 0, w, h}, {0.62f, 0.80f, 0.93f, 1});       // 空
    s.drawCircle({w * 0.5f, h * 0.5f}, 80, {1, 0.9f, 0.4f, 1}); // 太陽
  }
private:
  float m_t = 0;
};

int main() {
  mitiru::Engine engine;
  MyGame game;
  mitiru::EngineConfig cfg;
  cfg.title = "My First Mitiru Game";
  cfg.windowWidth = 1280;
  cfg.windowHeight = 720;
  engine.run(game, cfg);
}
01 はじめて触る 5 分でビルドして、最初のウィンドウを開きます。 02 つくってみる 小さなノベルや 2D ゲームをつくりながら、エンジンの考えかたを覚えます。 03 動くサンプルを見る すぐに走る 14 個のサンプル。コード付き。

どんなエンジン?

01

C++ でゲームを書く

シーンの進行、状態、ノベルの分岐、物理、AI。「動き」の部分は全部 C++ で書きます。 デバッガで止められて、プロファイラで測れて、テストできる。 ふだんの C++ の感覚そのままです。

02

UI は HTML/CSS で組む

メニュー、HUD、ダイアログボックス、トランジション。 画面まわりは Web の道具で組みます。CSS でアニメーションを書けて、 Web のデザイン資産がそのまま生きます。エンジン内蔵の CEF が表示まわりを担当します。

03

橋は薄く

JS → C++ は「何が起きたか」を渡すだけ。C++ → JS は「何を表示してほしいか」を渡すだけ。 ゲームの状態は C++ 側にひとつだけ持つので、何が正解かで迷いません。

中身の話

ヘッダだけで動く

47 個の名前空間で構成されたヘッダ群を、CMake の FetchContent で取り込んで 1 つのターゲットに link するだけ。プリビルドされた .lib や .dll を 配って回る必要はありません。

グラフィックスの裏側を選べる

DX11 / DX12 / Vulkan / OpenGL / WebGL / Null を同じ IDevice で扱います。 開発機では DX12、CI のヘッドレス環境では Null に自動で切り替わるので、 機械を選ばずビルドが通ります。

Tracy ですぐ測れる

Tracy プロファイラがあらかじめ繋がっています。 フレームのどこに時間がかかっているか、GPU タイムラインも含めて、 ほぼコードを書かずに見られます。

セーブデータが壊れにくい

JSON ベースのセーブとマイグレーション API がついています。 スキーマを変えても、古いセーブが読み込めるしくみが用意されているので、 リリース後の更新で「ロード不能」になる事故を避けられます。

データは JSON Schema で守られる

ノベルスクリプト、ローカライズ、バランス調整表、アートバイブル。 ゲームに食わせる前に Schema で検証されるので、 形が違うデータが入り込んで沈黙バグになる事故が減ります。

テストの土台が用意されている

Catch2 ベースの単体・統合テストがすでに動いています。 ブラウザを必要とする検証は Playwright と Chrome DevTools MCP を併用するので、 UI が壊れた瞬間に気付けます。
