// MitiruEngine — C++20 game engine

ゲームのルールは C++、画面は HTML / CSS。

状態を 1 個の flat POD に置く軽量 C++ ゲームエンジン。2D も 3D も。全部入りエディタを持たず、必要な道具だけを個別ウィンドウに出す。決定的な実行と壊れにくさを土台に、巻き戻し・録画再生・AI による全状態観測が同じ仕組みから生えてくる。

01 はじめてのゲーム作って動かすまでを 1 本のチュートリアルで。 02 機能リファレンス描画・入力・音・演出・当たり判定の逆引き。 03 画面を作るHTML / CSS で HUD・メニューを作る (JS 不要)。 04 配布する1 つの zip にまとめて配る。中身も隠せる。

できること

小〜中規模のゲームに要るものは、ひととおり揃えてあります。使うものだけ取り出して使えます。

  • HTML / CSS で画面 web-ui

    メニューや HUD を Web と同じ書き方で。CSS アニメーションもそのまま。手書き JS は不要。

  • 2D も 3D も 2d / 3d

    スプライト・タイルマップの 2D から、3D モデル表示まで扱えます。

  • 手応えのある演出 juice

    パーティクル・画面の揺れ・一瞬止まる演出で操作の手応えを足せます。

  • 音 audio

    効果音・BGM を鳴らせます。

  • コマンドひとつ cli

    mitiru new で作って mitiru run で動かす。エディタは好きなもので。

  • 書き換えながら動かす hot reload

    保存すると、ゲームを止めず状態を保ったまま反映。

  • 土台がそろっている batteries

    セーブ・入力 (キー / マウス / パッド)・通信などの部品が同梱。

  • AI が全状態を読める AI Lens

    フィールドを宣言するだけで、現在も過去も JSON で読める。差分・反実仮想まで。

核心 — 状態は 1 個の flat POD

ゲームの状態を 1 つの平坦な構造体（FixedVec / FixedString で固定長化）に置く。たったこれだけで、本来は別々に作り込む重い機能が 同じ memcpy + 記述子から追加コストなしで 生えてきます。制約が機能を生んでいる——これが MitiruEngine の核心です。

  • 巻き戻して観察 time-travel

    毎フレームの状態をそのまま記録。1 フレームずつ巻き戻して「なぜ HP が 50 になった」を原因の 1 行まで追えます。

  • 録画してテストに replay-as-test

    入力と乱数の種を記録し、同じプレイを bit-exact に再現。リプレイがそのまま回帰テストに。

  • AI が全状態を読む AI Lens

    MITIRU_REFLECT で宣言 → MITIRU_AI=1 で /api/ai/state・/diff・/branch。AI が状態を読み・差分し・「この入力を続けたら?」を試せます。

  • コンパイルが守る guarded

    MITIRU_GAME が flat POD をコンパイル時に強制。うっかりポインタを混ぜたらその場でエラー。構造保証が崩れません。

1 つの設計判断が差別化の土台になっている、という考え方。詳しくは 機能リファレンス §AI Lens へ。

必要なものしか、画面に出さない

巨大なエディタの全機能に圧倒されることがありません。1 つの道具 = 1 つの関心事 = 1 つのウィンドウ。要るものが、要るときに出ます。

  • 道具は別ウィンドウ sub-window

    デバッグ道具は別の OS ウィンドウで開きます。ゲーム画面は汚れず、スクショに余計なものが映りません。

  • 止めずに書き換え hot reload

    mitiru watch で、保存のたびに止めず・状態を保ったまま反映。HTML / CSS の編集もすぐ画面に。

  • 部品ごとに単独起動 per-system

    描画だけ・音だけ、と見たい部品を単独で立ち上げ。全体を起動せず触りたい部分だけ。

はじめる

mitiru new から mitiru run まで、触るファイルは C++ と HTML の 2 つだけ。

# 新規プロジェクトを作って動かす
mitiru new my-game
cd my-game
mitiru run
