セーブと巻き戻し

遊んだ途中を章の名前つきでスロットに書き、物理エンジンの世界ごと巻き戻します。

起動は mitiru_host.exe physics_rewind/physics_rewind.dll です。Space で人形を蹴り、R で最初からやり直します。全文はサンプル集にあります。サンプルのビルドの仕方と起動する場所は、1 ページ目の始め方にあります。

状態を 1 つの struct に置く

1 ページ目から、ゲームの状態は数値だけの 1 つの struct に置いてきました。エンジンはこの中身を毎フレーム記録するので、巻き戻し、リプレイ、セーブは同じ仕組みで動きます。セーブは、この struct をファイルに写すことです。

スロットに書く

hud.saveSlot は、スロットに章の名前を付けて書きます。スロットのファイルには、保存した時刻、遊んだ時間、そのときの画面を縮めたサムネイルも入ります。書き込みは一時ファイルに書き終えてから差し替え、前の版を残します。書いている途中でゲームが止まっても、前のセーブは読めます。

if (in.pressed(Key::F5)) { hud.saveSlot("slot1", "第 2 章 鍛冶屋の村"); }
if (in.pressed(Key::F6)) { hud.load("slot1"); }
if (checkpointReached)   { hud.save("auto"); }   // 自動セーブの枠に順に書く

// ロード画面を開くときに 1 度頼むと、次のフレームに新しい順で最大 8 個届く
hud.listSlots();

for (int i = 0; i < in.slotCount(); ++i)
{
    const module::SlotSummary* s = in.slot(i);   // s->slot、s->chapter、s->playtimeSec
}

F7 から F12 は mitiru_host が一時停止や時間の速さの切り替えに使い、同じキーがゲームにも届きます。ゲームの操作には F1 から F6 か、ほかのキーを使います。一覧は 機能リファレンスにあります。

セーブもロードも、エンジンが update の後に行います。結果が分かるのは次のフレームです。in.saveSucceeded() は直前の結果を次のセーブまで持ち続けるので、2 回目のセーブが終わったフレームはこれだけでは分かりません。「いまセーブが終わった」を知りたいときは、SaveWatch を struct に 1 つ置いて、update の最初に poll を呼びます。

#include <mitiru/module/SaveWatch.hpp>

struct Game
{
    mitiru::SaveWatch saves;
    // ...
    void update(Input in, Hud hud, float dt)
    {
        saves.poll(in, hud);
        if (saves.saved()  == SaveResult::Ok)     { toast = "セーブしました"; }
        if (saves.saved()  == SaveResult::Failed) { toast = "セーブできませんでした"; }
        if (saves.loaded() == SaveResult::Ok)     { toast = "ロードしました"; }
        if (in.pressed(Key::F5)) { saves.save(hud, "slot1", "第 2 章 鍛冶屋の村"); }
        if (in.pressed(Key::F6)) { saves.load(hud, "slot1"); }
    }
};

saved() と loaded() は、終わったフレームにだけ Ok か Failed を返し、ほかのフレームは None です。セーブもロードも、頼んだ次のフレームに結果が出ます。結果を待っている間 (saves.busy()) の save と load は受け付けず、false を返します。hud.save で直接書いたセーブを読んだときも、loaded() は立ちます。

同梱サンプル save_slots は、この一覧を画面 (RML) に出します。C++ が in.slot(i) から「スロット 1: 花 3 本、遊んだ時間 0:42」のような行を組んで hud.set で送り、UI のボタンは dispatch('slot.save', 'id', 1) のように操作の名前を C++ へ返すだけです。全文はサンプル集にあります。

セーブの置き場はエンジンが決めます。DLL の隣に ship.json を置いてゲームの名前を書くと、セーブは %APPDATA%/ゲームの名前/saves/ に入ります。ダブルクリックで起動しても同じ場所を使います。

ゲームを作り変えて struct の形が変わると、古いセーブはそのまま写せません。ロードでは、形が同じならそのまま写します。違っていれば、MITIRU_REFLECT に載せた欄のうち名前と型が合うものだけを移します。どちらもできなければ読み込みを断り、in.loadSucceeded() が false になります。

物理の世界ごと巻き戻す

struct に置けない状態もあります。物理エンジン Jolt Physics の世界や、3 ページ目の群衆は、ライブラリの中にポインタで持たれています。こうした状態は、保存と復元の 2 つの関数を持つ窓口としてエンジンに預けます。エンジンは struct と同じフレームに窓口の中身も記録し、巻き戻すときは両方を戻します。

#include <mitiru/module/SideState.hpp>
#include <mitiru/physics/JoltGameWorld.hpp>

// 物理の世界を組み立てる。何度呼んでも同じ物を同じ順で置く
void buildWorld(JoltGameWorld& world, const void* /*state*/)
{
    // 床、箱 45 個、人形を world.addBody / world.addRagdoll で足す
}

JoltGameWorld g_world(&buildWorld);
MITIRU_SIDE_STATE("jolt", 1, g_world);   // 名前、中身の形の番号、預ける物

void update(Input in, Hud hud, float dt)
{
    g_world.ensureBuilt(this);   // 無ければ作る (ホットリロードの直後も同じ)
    g_world.step(dt);
    for (int i = 0; i < kBoxes; ++i) { boxes[i] = poseOf(g_boxes[i]); }   // 描く位置は struct へ写す
}

void init() { g_world.reset(); }   // 最初からやり直すときは、物理の世界も作り直す

守ることは 3 つです。世界を組み立てる関数は、何度呼んでも同じ物を同じ順で作ります。弾のように出し入れする物は組み立ての中で作っておき、spawn と despawn で出し入れします。描く位置と向きは毎フレーム struct に写し、draw ではそれを読みます。物理は 1 つのスレッドで解くので、同じ入力からは同じ中身になります。

mitiru new で作ったプロジェクトで Jolt を使うときは、mitiru.toml の [engine] features に "jolt" を書きます。Jolt の入っていないエンジンを指していると、ビルドの最初に止まって直し方を出します。

窓口を預けたゲームでも、セーブ、ホットリロード、録画の照合はそのまま使えます。セーブのファイルには struct の後ろに窓口の中身が続きます。録画を照合する --replay-test は窓口の中身も毎フレーム比べ、食い違えば窓口の名前を出して失敗します。

巻き戻してみる

mitiru_host.exe physics_rewind/physics_rewind.dll --inspect rewind で起動すると、ゲームの窓の下に巻き戻しのバーが付きます。人形を蹴って箱を崩したあと、バーをつかんで左へ動かすと、箱と人形がそのフレームの位置へ戻ります。窓口の中身も同じフレームへ戻るので、物理の世界だけが先のフレームに残ることはありません。
