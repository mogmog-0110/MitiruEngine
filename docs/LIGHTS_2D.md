# 2D ライト

2D の絵に光を当てる。暗い部屋を松明で照らす、洞窟を提灯で歩く、といった場面を、絵を描き直さずに作れる。章の例は [`examples/lights2d`](../examples/lights2d/lights2d_dll.cpp)。

## 使い方

1. `mitiru.toml` の `[render] needs` に `light_2d` を書く (2D だけのゲームは `no_3d` も)。書かないゲームは、宣言のない旧体制として光の資源を起動で作る。宣言があって `light_2d` が無いと、光は当たらず 1 度だけ知らせる
2. 描画の中で、環境光と灯を呼ぶ。呼んだ後に描いた物へ、ゲームの描画の終わりまで光が当たる

```cpp
canvas.ambient2D(Color{0.45f, 0.52f, 0.8f, 1.0f}, 0.3f);   // 灯の届かない所の明るさ。呼ばなければ黒
render::Light2DPod torch;
torch.x = 400; torch.y = 300;      // 論理座標 (カメラを通した後の位置で光る)
torch.height = 70;                  // 面から浮いている高さ。法線マップのある絵の陰影に効く
torch.radius = 380;                 // 届く距離
torch.color[0] = 1.0f; torch.color[1] = 0.72f; torch.color[2] = 0.42f;
torch.intensity = 1.3f;
canvas.light2D(torch);              // 毎フレーム呼ぶ。最大 16 灯
```

円錐の灯 (スポット) は `coneDeg` (外側の半角) と `directionDeg` (向き。画面で時計回りが正) を足す。減衰は `falloff` で、1 が直線、2 が二乗になる。

## 光が当たる物と当たらない物

- 当たる: `ambient2D` / `light2D` を呼んだ後に描いた矩形・円・線・画像・文字
- 当たらない: 呼ぶ前に描いた物 (背景や章ラベルを先に描けば、暗くならない)、クリアの色、角丸と円の SDF 描画 (`drawStyledRect` / `drawStyledCircle`)、3D と同じフレームの 2D、CPU 描画 (観測用の画面バッファ)
- ゲームの描画が終わると光は落ちる。デバッグ描画、暗転、字幕の覆いには当たらない
- DX12 と Dawn が対象。DX11 には当たらず、使うと 1 度だけ知らせる
- 影 (遮蔽物) は今は無い

HUD は光を当てたくないので、RmlUi に置くか、光の呼び出しより前に描く。

## 法線マップ

絵に凹凸の陰影を付けるには、同じ大きさの画像を、名前に `_n` を付けて隣に置く。

```
assets/sprites/barrel.png     色の絵
assets/sprites/barrel_n.png   法線マップ
```

`sprite("barrel", ...)` のように id で描く絵だけが、`_n` を引く。色は赤が画像の右、緑が画像の上、青が手前 (Unity や Godot と同じ向き)。左右反転や回転をしても、法線は絵と一緒に向きを変える。スプライトシートの切り出しは、色と法線で同じ UV を使うので、同じ配置の法線シートを 1 枚置けばよい。

法線マップが無い絵は、距離の減衰だけで明るくなる (高さで暗くならない)。画像の大きさが色と違う `_n` は使わず、1 度だけ知らせる。

## 式

光の合計 = 環境光 + 各灯の `色 x 強さ x 減衰 x 円錐 x 向き`。画素の色にこの合計を掛ける (アルファは変えない)。式は [`Light2DMath.hpp`](../include/mitiru/render/Light2DMath.hpp) にあり、DX12 と Dawn の描画は、同じ式の CPU の値と画素まで合うことを試験で確かめている。設計は ADR 0103。
