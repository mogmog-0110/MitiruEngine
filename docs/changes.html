更新履歴

バージョンごとの変更点です。公開したバージョンは GitHub の Releases にあります。

v0.48.0

v0.47.0 からの更新です。ABI は v61 から v62 に上がるため、ゲームの DLL は v0.48.0 で組み直す必要があります。入力とウィンドウ、描画、動画、音、アクセシビリティ、物理を広げ、Dawn の cache とモデルの先読み、巻き戻しの記録を改善しました。

mitiru-cli v0.18.0 も同時に公開します。

移行

  • mitiru build でゲームの DLL を組み直してください。host は ABI の版の完全一致を要求し、古い DLL は読み込みの時に「ABI番号が違う」と明示のエラーで断ります。
  • ABI v62 の理由は、ゲーム DLL と host の間の型を変える追加 12 件を 1 回の版上げにまとめたこと (ADR 0099) です。入力の秒数、OS のアクセシビリティ設定、表示の情報、モニタと音の機器の選択、パッドの番号、縦書き、動画、2D ライト、自作の材質、モーフターゲット、HDR の環境、SceneLook の湿り気・雲・色の LUT の入口を足しました。
  • InputSnapshot の大きさは変わりません。古い録画 (.mtrr の形式 4、5、6) はそのまま読めます。
  • v62 の途中のコミットで組んだ DLL も組み直してください。RenderPipeline2D の大きさが増えたためです。ABI の番号が同じなので読み込みは黙って通りますが、光や動画を使う古い DLL は黙って何も起きません。
  • 巻き戻しの MITIRU_SIDE_STATE で預ける Jolt の world の保存を JLT2 から JLT3 に上げました。拘束の構成を保存に含めるため、旧 JLT2 の保存は読めません。
  • 視点操作のマウスを Raw Input で取ります。値の単位が変わるため視点の感度が変わります。MITIRU_LEGACY_MOUSE_LOCK=1 で従来の取り方に戻せます。
  • 入力の既定を、文字ではなく物理的なキーの位置にしました。input.keyMode = character で従来の文字による割り当てに戻せます。
  • トリガーとスティックに既定の整形が入ります。トリガーの半押し 0.5 は約 0.43 になります。スティックは円形のデッドゾーンと外側の飽和により、斜めの全力の長さが 1 になります。
  • RmlUiHost::setText は、同じ文字列を送り続けても UI を読み直しません。同じ文字列による毎フレームの読み直しに頼っていたゲームは、値を変えて送ってください。
  • v62 で入口だけを足し、中身がまだ無い機能があります。縦書き (drawTextVertical は横書きで描きます)、濡れた面 (SceneLook::wetness)、雲の層 (SceneLook::cloudCover)、HDR の環境 (environmentHdr3D) は、使うと 1 度だけ知らせ、絵は変わりません。

描画

  • 描画の機能が DX12、Dawn 通常、Dawn 互換のどれで動くかは、docs/3D_RENDERING.md の機能表を正とします。
  • DX12 に点光源の影を足しました。LocalLight::castShadow を付けた点光源のうち、提出順で先頭の 1 灯が 1024x1024 の 6 面へ影を落とし、24 MiB を使います。[render] needs に point_shadow を宣言したゲームだけで作り、宣言のない旧体制は影なしのままです。
  • SMAA を DX12 と Dawn に足しました。上流 iryoku/smaa の同じコミットから SMAA.hlsl、AreaTex.h、SearchTex.h を入れ、表は約 1.2 MB です。aaMode 4 または --aa smaa で選びます。既定は FXAA のままで、主ビューだけに使い、副ビューは FXAA です。
  • 1080p の DX12 における GPU p50 は、MSAA のみが 0.231 ms、FXAA が 0.272 ms、SMAA が 0.293 ms です。階段状の辺の誤差 (輝度、0〜255) は、階段のままの 12.7 から SMAA で 1.25 になりました。
  • 自作の陰影・材質を足しました。assets/materials/<name>.slang に material() を書き、<name>.mat.json でパラメータを宣言します。照明、影、輪郭線はエンジンのままです。DX12 と Dawn で動きますが、Dawn は tools/bake_materials.py が焼いた .wgsl を読み、トゥーンの陰影だけに効きます。半透明の描画には効きません。例は examples/material3d です。
  • PBR に glTF の KHR_materials_clearcoat、anisotropy、sheen の層を足しました。DX12 のみで、Dawn は層を描きません。
  • 法線マップつきの 2D ライトを足しました。ambient2D と light2D を呼んだ後に描いた物へ光が当たり、灯は最大 16 です。名前に _n を付けた画像を法線マップとして使います。DX12 と Dawn で動きますが影はありません。[render] needs に light_2d を宣言します。例は examples/lights2d です。
  • 3D LUT、ビネット、フィルムグレインによる色の仕上げを足しました。assets/color_looks.json に宣言し、SceneLook::colorLut に番号を入れます。LUT は一辺 N の立方体を幅 N*N、高さ N の PNG に並べ、tools/cube_to_lut_png.py で .cube から作れます。DX12 と Dawn の互換でも動きます。
  • DX12 に HDR 出力を足しました。Present だけを scRGB (FP16) にします。graphics.hdr を auto にするか、mitiru_host --hdr で使い、既定は off です。キャプチャ、リプレイ、VRT は SDR のままです。Dawn は色管理を受け付けず SDR のままで、HDR10 は未対応です。
  • glTF の morph target をゲームの重みで足して描くモーフターゲットを加えました。drawModelPose に重みを渡します。表情は VRM 1.0 の expressions と同じ形の <model>.expressions.json、口の形は tools/bake_visemes.py が音声から焼く時刻表を使います。FBX の blend shape も取り込みます。DX12 と Dawn で動き、スロットは 128 までです。例は examples/face3d です。
  • Dawn の列が「なし」の機能には、点光源の影、HDR 出力、PBR の層、AO、TAA、被写界深度、反射 (SSR)、動く間接光 (DDGI) などがあります。
  • 影を使わない lights256 の GPU p50 は、点光源の影を足した変更により RTX 5070 Ti で約 2% 遅くなり、1.021〜1.027 倍になりました。不透明パスは 0.234 ms から 0.246 ms に伸びました。ほかの 16 場面と OOZE DRIVE の 4 場面は 0.97〜1.03 倍に収まりました。この退行は直していません。

動画

  • MPEG-1 (.mpg) を Screen::drawVideo で映します。復号には pl_mpeg を使い、mitiru.toml の [engine] features に video を書いたビルドだけへ入り、host は約 31 KB 増えます。
  • 映す 1 コマはゲームの時刻 (秒) だけで決まり、壁時計と音の時計は見ません。巻き戻し、--capture-dir の撮影、決定論リプレイが動画の絵まで届きます。ゲームの状態に置くのは動画の秒 (float 1 つ) だけです。
  • 音は assets/audio/<名前>.ogg または .wav に分けて置きます。H.264 と MP4 は読めません。
  • カットシーンの Sequence の JSON に videos を書けます。例は 8 秒のタイトル映像を含む examples/title_video です。Dawn の 2D に画像を重ねる経路も足しました。
  • mitiru-cli v0.18.0 の mitiru dist は動画の欠けを検査します。

音

  • 5.1 / 7.1 の PC で効果音のバス (残響とダッキング) が作られない穴を直し、機器を開く時のミックスを 2ch・48 kHz に固定しました。
  • 出力機器を F1 のデバッグメニューの「Audio output」で名前から選び、audio_device.json に残せます。
  • 機器を開けない時は Null の機器で鳴らし続け、5 秒ごとに開き直します。使用中の機器が失われた時と既定の機器が替わった時にも追従します。
  • バスを group の木にし、効果の鎖を差す口とバスごとの残響への送りを足しました。パラメトリック EQ とコンプレッサは mix.json に書けます。master の limiter は opt-in で、既定では掛けません。
  • EQ、コンプレッサ、limiter の数値は試験で見ていますが、聴感は未確認です。

入力、ウィンドウ、アクセシビリティ

  • キーを物理的な位置で束縛する層を足して既定にし、キーの刻印は配列に合わせて出します。スティックとトリガーの円形のデッドゾーン、外側の飽和、応答曲線は設定で変えられます。
  • 長押し、ダブルタップ、chord、リピートの時間パターンを足しました。秒数は利用者の設定で、InputSnapshot に入ります。
  • 割り当て表を、修飾キーとホイールの割り当て、機器ごとの初期値、重なりの表示まで広げました。
  • DPI と表示構成の変化に追従します。モニタを名前で選べ、Alt+Enter で graphics.windowMode を切り替えられます。リフレッシュレートと HDR の能力をゲームが読めます。
  • UI の入力欄のコピーと貼り付けを OS のクリップボードにしました。パッドのプレイヤー番号 (LED) も設定できます。
  • OS の高コントラスト、動きの軽減、透明効果の軽減を取り込みます。設定ファイルが無い最初の起動は、OS の「アニメーション効果」が切れていれば画面の揺れを 0 で始めます。
  • UI Automation で Narrator に字幕と通知を読ませます。RML の要素に data-a11y を付けます。UI の木であるボタンやスライダーは読めません。
  • 字幕を効果音と話者へ広げました。sounds.json の caption に文のキーと種類 (dialogue、ambient、music、alert) を書き、accessibility.captions で出す種類を選びます。例は examples/captions です。
  • tools/grab_scene.py の --cvd と --contrast で色覚とコントラストを検査できます。コントラストは文字ごとに pass、fail、unknown を出します。

物理

  • Jolt の world に、固定、点、ヒンジ、スライダー、距離、円錐、SwingTwist の汎用ジョイントを足しました。breakJoint で壊せます。
  • 巻き戻しの保存に拘束の構成を含めました。body とジョイントの組が違う bytes は戻さずに断ります。吊り橋のジョイントを壊す場面を試験の fixture に足しました。

性能

  • 計測は DX12、RTX 5070 Ti、1920x1080、Release で、前後を同じ回の中で交互に 3 回ずつ流した中央値です。perf_bench.py に尾 (p99/p50) と、立ち上がり後のパイプライン作成を測る列を足しました。
  • 確保 0 を全場面のゲートにしました。定常フレームの 1% を超えて確保が出る場面と、立ち上がり後にパイプラインやシェーダーを作る場面は perf_bench.py --check が赤にします。例外は理由つきの許容リストに書きます。
  • デバッグメニューが閉じている間の毎フレームの行の写しを消し、全場面の 1 フレーム 1 回の確保をなくしました。crowd200 で確保が出たフレームは 580 から 14 になりました。
  • 敵の大群で、確保が 6 回を超えたフレームは 25 体で 17 から 7、100 体で 49 から 11、200 体で 88 から 23 になりました。p99 は horde25 が 1.97 ms から 1.64 ms、horde100 が 4.07 ms から 3.71 ms、horde200 が 6.46 ms から 6.10 ms です。
  • 台本実行の 60 Hz の待ちを 60 Hz の格子で数え、周期の平均を 16.681 ms から 16.666 ms にしました。
  • RmlUiHost::setText の変更により、OOZE DRIVE の stage_s1 は確保が 1 フレーム 1406 回から 1286 回、走った時間の p50 が 8.10 ms から 7.67 ms になりました。
  • Dawn の変換結果を DX12 のシェーダーと同じ場所に残します。Dawn 通常の crowd200 は、2 回目以降の最初のフレームが 1247 ms から 19 ms、起動が 552 ms から 314 ms になりました。cache は 94 ファイル、680 KB です。最初の起動は 1.2 秒のままです。MITIRU_DAWN_NO_DISK_CACHE=1 で切れます。
  • Dawn のモデル読み込みをワーカーの前半とメインスレッドの後半に分け、先読みできるようにしました。stream で実時間が 25 ms を超えたフレームの最大は、Dawn 通常が 416 ms から 36 ms、互換が 387 ms から 18 ms です。メインスレッドの最大は通常が 390 ms から 3.9 ms、互換が 351 ms から 3.8 ms です。400 ms の停止 1 回を 3〜5 ms の 12 回に分けました。先読みしない stream_settled は変わらず、実時間の最大は 403 ms から 380 ms です。
  • dawn を書いたプロジェクトの mitiru dist は、Dawn の変換結果も焼いて配布物の shader_cache に同梱します。bench_skinned200 の host の実時間は、Dawn 通常で空の cache の最初の起動 3813 ms から配布物の cache を読む 2 回目 1516 ms、互換で 4360 ms から 1234 ms になりました。
  • coop3d の尾は直せず、尾のゲートの差の閾値を 1 ms から 1.5 ms に広げました。
  • GPU なしで巻き戻しとシミュレーションを測る tools/sim_bench.py を足しました。Core i7-13700F で前後を 7 回ずつ交互に測ると、巻き戻しの記録は GameMemory 256 KB が 77 µs から 24 µs、1 MB が 265 µs から 129 µs、4 MB が 887 µs から 535 µs、群衆 200 体が 216 µs から 35 µs、物理 200 個が 232 µs から 56 µs、敵 100 体が 182 µs から 46 µs、敵 400 体が 779 µs から 317 µs になりました。
  • 「小さな状態で 1 フレーム 0.1 ms 未満」は、GameMemory 256 KB まで、群衆 200 体、物理 200 個、敵 100 体で達成しました。1 MB、4 MB、敵 400 体は届きませんでした。
  • MITIRU_SIDE_STATE の hash は読む側が bytes から同じ値を出し、記録側では 0 にしました。差分の持ち方も替えましたが、状態は前と bit 単位で同じです。代償としてリングの確保は、1 MB の GameMemory で 6 MB から 36 MB、敵 400 体で GameMemory と MITIRU_SIDE_STATE を合わせて 32 MB から 63 MB に増えました。
  • 尾 p99 は crowd200 が 0.68 ms から 0.38 ms、physics200 が 0.56 ms から 0.30 ms、horde100 が 0.59 ms から 0.37 ms、horde400 が 2.54 ms から 1.93 ms になりました。
  • 敵 400 体の 1 フレーム 1.45 ms のうち dtCrowd::update が 67% です。外部のコードで、bit 一致のまま速くするには Detour の複製が要るため入れていません。

届かなかったことと未確認

  • Dawn の確保は 1 フレーム 100〜340 回、互換のスキンでは 3000 回前後残ります。大半は Dawn の内部です。
  • OOZE DRIVE の RmlUi の文字の組みは 1 フレーム 600 回余り残ります。
  • 別の GPU で Dawn の cache が当たることは実測していません。cache のキーに vendor、device、driver の値が無いことだけ確かめました。
  • coop3d の毎回同じ 3 フレーム (127、255、633) の原因は追えていません。
  • Dawn の switchStage はモデルを手放しません。Dawn のモデル 1 件の後半 (3〜5 ms) をフレームをまたいで分けることもしていません。
  • ウィンドウの Present と vsync のペーシング、中くらいの GPU での p99 は実測していません。
  • Dawn 互換の lights256 は、p99 が p50 の 2 倍かつ 1.5 ms 超という尾のゲートに当たります。v0.47.0 の host でも同じ値で、退行ではありません。
  • 実機では、マウスの Raw Input の手触り、US 以外の配列のキーボードでのキー位置の束縛、本物のパッド、複数モニタでの DPI とウィンドウの移動、Alt+Enter による表示の形の切り替え、音デバイスの抜き差し、HDR モニタでの見た目、Narrator の聞こえ方、EQ、コンプレッサ、limiter の聴感、ウィンドウのある実機での動画再生を確認していません。パッドにはスティックとトリガーの整形、LED のプレイヤー番号を含みます。開発機のモニタは SDR です。

  • 一式を組む前の検査で、欠けていた新しい 4 つの例、8 本の文書、5 本の道具を見つけて足しました。例は captions、face3d、lights2d、material3d、道具は bake_materials.py、gen_dawn_shaders.py、bake_visemes.py、cube_to_lut_png.py、make_title_video.py です。

  • Dawn ありの Release の mitiru_dawn_tests は 102 ケースのうち 97 が通り、危険な試験 5 が skip です。assertion は通常の 1300 件、互換の強制の 1294 件がすべて通りました。

  • features に video を書かず、assets/video に動画を置いたプロジェクトは、mitiru dist が組む前に止めます。

mitiru-cli v0.18.0

  • 新規プロジェクトの既定の engine は 0.48.0 です。
  • [engine] features に video を足しました。書いたプロジェクトだけ pl_mpeg が入ります。
  • mitiru dist は、assets/video に動画があるのに features に video が無いゲームを組む前に止め、配布物に動画が写っていないことも検査します。

v0.47.0

v0.46.1 からの更新です。ABI は v60 から v61 に上がるため、ゲームの DLL は v0.47.0 で組み直す必要があります。2D と 3D の描画をまとめ、起動時の時間とメモリを減らし、Dawn の 3D 描画を速くしました。

mitiru-cli v0.17.0 も同時に公開します。

移行

  • mitiru build でゲームの DLL を組み直してください。host は ABI の版の完全一致を要求し、古い DLL は読み込みの時に明示のエラーで断ります。
  • ABI v61 の理由は 2D の積み方 (ADR 0092) です。ゲーム DLL が inline で持つ Screen の中身の配置が変わりました。InputSnapshot、FrameIntents、SceneLook、DrawContext は変わりません。
  • Screen に drawSpriteRegions と stopQuadBatching を足しました。drawSpriteRegions は同じテクスチャの切り出しを同じ色で何枚か描きます。既存の呼び出しはそのまま動きます。
  • 2D だけのゲームは、[render] needs に no_3d を書けます。3D の層を何も作らなくなります。書かない既存のゲームは今までどおりです。
  • MITIRU_QUAD_BATCH=0 で DX12 の 2D の四角形のレコードを切り、従来の頂点バッチだけにできます。MITIRU_DRAW_MERGE=0 で 3D のまとめ描きを切れます。

2D (DX12、ADR 0092)

  • 軸に平行な四角形である画像、矩形、文字、枠を、4 頂点と 6 添字の 152 バイトでなく、1 枚 48 バイトのレコードで積みます。GPU が 4 隅に広げます。

  • 起動に失敗したとき、理由と GPU の情報を boot_report.txt 1 つにまとめて残します。置き場は exe の隣、%LOCALAPPDATA%、一時フォルダの順で、書けた最初の場所です。画面には、このファイルを送ってもらう文とパスを出します。

  • セーブ、記録、一時フォルダ、ゲームの DLL の写しに書けない PC では、書ける場所へ回して起動します。
  • host が GPU の区分 (software、integrated、discrete) を環境変数 MITIRU_GPU_CLASS でゲームに渡します。ゲームは最初の画質を決めるのに使えます。
  • 重いときに 3D の内部解像度を段階的に下げる render/DynamicScale.hpp を足しました。

  • 試作 (spikes/multiplatform/) では、Dawn の D3D12・D3D11・Vulkan とヘッドレスの Chrome で同じ絵が出ました。

v0.44.0

v0.43.0 からの更新です。ABI は v57 から v59 に上がりました。どのゲームでも使えるデバッグメニューと、描くフレームが tick より多いときに視点をなめらかにする値を足しました。

デバッグメニュー (ADR 0085、ABI v59)

  • F1 (パッドは LS と RS の同時押し) で開くデバッグメニューを足しました。ゲームは項目 (見出し、ボタン、トグル、数値、選択肢、読むだけの 1 行) を返す関数を MITIRU_DEBUG_MENU で登録します。見た目と操作はエンジンが受け持ちます。
  • 選んだ項目は、次の update に操作として届きます。録画に残るので、リプレイでも同じフレームに届きます。
  • 開いている間はゲームを止め、入力をゲームに渡しません。FPS の表示、コマ送り、速さ、画面の保存、ログとセーブのフォルダ、ツールのウィンドウは最初から入っています。
  • 開発用のキー (F1 のメニューと F7〜F12) を、起動の引数 --no-dev-keys、ship.json の "devKeys": false、ゲームの devToolsOff(true) のどれか 1 つでまとめて切れます。使い方は docs/DEBUG_MENU.md と docs/HOST_KEYS.md にあります。

描画 (ADR 0084、ABI v58)

  • Screen::tickAlpha() を足しました。前の tick から今の tick までの進み具合 (0〜1) です。60 Hz の tick より速いモニターでも、描くときに補間できます。
  • mitiru/action/CameraBlend.hpp の blendCameraView で、前と今の視点を補間します。視点が大きく飛んだときは補間しません。
  • ウィンドウを出さずに確かめるため、mitiru_host --tick-alpha を足しました。

リプレイ・入力

  • RegistrySideState が部品を保存するとき、構造体の詰め物を 0 にします。値が同じなら、保存した bytes も同じになります。
  • パッドの振動を 4 つまで重ね、モーターごとに強い方を出します。弱い振動が、短く強い振動を消しません。

ツール

  • motion_tune。ゲームを巻き戻しで止めたまま試した値を、捨てられるようにしました。幅が狭いウィンドウでは、軌跡の列を下へ回します。
  • stage_edit。数値の入力に打ち直して通った値に、前の誤りが残らないようにしました。

移行

v0.43.0

v0.42.0 からの更新です。ABI は v52 から v57 に上がりました。流れる体 (ソフトボディ)、物ごとのトゥーンの見た目と金属、遮る物を透かす描画、ゲームから頼めるウィンドウの形、ステージやモーションを手で直せるツールを足しました。

描画

  • 物ごとのトゥーン (ADR 0079)。描画ごとに段、線、インパクトフレーム、平らな 2 色の粒を指定できます。.clod の直接光も段になります。
  • トゥーンの金属 (ADR 0083、ABI v57)。ToonStyle::metal で、空と地面を映す金属の質感を出します。amount が 0 の描画は今までと同じ絵のままです。使い方は 3D アクションを作る にあります。
  • 遮る物を透かす (ADR 0077)。カメラと的の間にある面を網点で透かす fadeOccluders3D を足しました。隠れた的はシルエットで見せます。シルエットは、的どうしの重なりを塗りません。
  • drawMesh と drawMeshInstanced に、照明の後に足す光を渡せるバージョンを足しました (ADR 0075、ABI v53)。
  • 頂点の数と並びが毎フレーム変わる面を、前の位置つきで送る updateMesh3D を足しました (ADR 0076、ABI v54)。
  • 影の深度を endFrame に別のリストで焼き、描画と同じフレームの形で影を落とします。歩くと太陽の影が点滅する問題を直しました。
  • 光を焼く場面に、回した箱と三角形の並びとレベルの .obj を入れられます。
  • 字の縁取りを、同じ絵のまま速く作ります。

流れる体

  • 粒で流れる体 (softbody) と、面の網を作る部品を足しました (ADR 0078)。参照実装と比べる道具とテストがあります。見本は examples/fluid3d です。
  • 小さな刻みの仕事をまとめ、近くの粒の表と面のセル探しを分けて回せるようにしました。時間は docs/ に測って書きました。
  • 位置が NaN や大きすぎる粒は、面を作る前に除きます。格子が配列に収まらないときは網を作りません。
  • FluidWorkers を作ってすぐ壊すと止まる問題を直しました。仕事の無い間は眠ります。

音

  • 1 フレームに鳴らせる音を 8 本から 32 本にしました。溢れたときは、止めと小さな音から捨てて知らせます。
  • 曲と効果音の low-pass を音声の処理の中で動かします。スイープでぷつぷつ鳴る問題を直しました。
  • 鳴らした直後の効果音を更新・停止すると、素材の全音量で鳴る問題を直しました。
  • --audio-realtime を足しました。音声スレッドを実時間で回して書き出します。

ゲームから頼める機能 (ABI v55、v56)

  • v55 (ADR 0080)。読み込みのマーカー、バスの高さと low-pass、曲の軸 (musicParams)、目の近くの粒を薄くする nearFadeStart / nearFadeEnd、起動中に出す絵、画質の段 (内部解像度と影の絵の大きさ)。
  • セーブの形が今と合わないときは、GameMemory だけを読めます。セーブの形が変わっても、クリア記録が消えません。
  • v56 (ADR 0081)。ゲームからウィンドウ / 枠なし全画面を頼む hud.windowMode(fullscreen, keepAspect)。縦横比を保つ全画面は、モニターの余白を黒で埋めます。

起動と診断

  • 起動の失敗を日本語の文で知らせます。GPU の選び方と診断ファイルを足しました。
  • ソフトウェア描画で動くときと、DX11 で 3D を描こうとして終了するときに、画面で知らせます。
  • 日本語などのパスに置いたゲームが動くよう、exe の ANSI を UTF-8 にしました。
  • フレームが 3 秒止まったとき、全スレッドのスタックを minidump に残します。ウィンドウが応答しないときも残します。
  • 端末の知らせを 1 文にしました。端末が読み出さない間も、知らせを別スレッドで書くのでウィンドウが止まりません。
  • JSON の書き間違いの知らせに、行と列を入れました。
  • CPU が埋まっていてもフレームが止まらないよう、待ち方とスレッドの優先度を変えました。

ツール

  • ツールのウィンドウを Windows 11 の標準アプリの見た目にそろえ、中の言葉を英語にしました。launcher と dev companion も同じ見た目です。
  • statemachine。ゲームの状態機械を図で見ます。今の状態、遷移の回数、直近の経過を出します。
  • stage_edit。ステージの JSON を図で直します。操作のスクリプトも書けます。「試す」と「残す」を分けます (ADR 0035、ADR 0082)。
  • motion_tune。調整値をスライダーで直し、記録した入力で軌跡を流しなおして、前と重ねます。
  • mitiru_tool --no-activate。ウィンドウを前面に出さずに開きます。
  • ゲームから頼まれたツールのために、host が HTTP API を開き、ウィンドウが閉じたら閉じます。
  • 遊んでいる間も、host とツールの exe を link し直せます。

開き方は 機能のページにあります。見た目の決まりは docs/TOOL_LOOK.md です。

カメラ・入力

  • カメラリグの画面の上を yaw の右から作り、注視点をならす前の上で上げました。腕に向きのばねと見通しの探索を入れました。ゲームが直に書いた yaw と pitch も、ばねを通さずに運びます。
  • 入力のスクリプトは D と U を down と up の略として読みません。矢印と動きの語のどちらとも読める行は誤りにします。
  • 実際のウィンドウで、左右の Shift・Ctrl・Alt を押したことにできます。
