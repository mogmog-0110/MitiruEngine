はじめかた

前提は Windows 10 / 11 だけ。下の手順で mitiru コマンドが入り、自分のゲームを作りはじめられます。（Linux / Mac は今後対応予定）

インストール手順

必要なものは 3 ステップで揃います。すでに入っている物は自動で飛ばすので、何度実行しても安全です。

  1. zip をダウンロードして展開 ── 最新リリース から zip を落として、好きな場所に展開します。
  2. installer.exe を実行 ── ダブルクリックすると、C++ ビルドツール（MSVC Build Tools・CMake・Windows SDK）と mitiru コマンドが入り、PATH に通ります。ツールを自分で管理したい人は、Build Tools を手動で入れて mitiru に PATH を通すだけでも構いません。
  3. プロジェクトを作って動かす ── PATH を反映させるため 新しいターミナルを開いてから実行します。
# 新規プロジェクトを作って動かす
mitiru new my-game
cd my-game
mitiru run

ウィンドウが開いてゲームのひな形が動きます。mitiru run はビルドして 1 回起動するコマンド。作り込み中は mitiru watch を使うと、コードを保存するたびに自動でビルドし直し、ゲームを止めずに反映されます（＝ホットリロード）。

初回ビルドだけ、5〜10 分かかります。 HTML UI 用の CEF（Chromium）を一度だけコンパイルするためです。2 回目以降は数秒。エディタは Visual Studio / VS Code / Vim / メモ帳、好きなもので構いません。うまくいかないときは mitiru doctor で環境を診断できます。

すぐ動くサンプルを覗きたいだけなら、展開した zip の中の MitiruEngine_Launcher.bat をダブルクリックすると、一覧から選んで起動できます（コンパイラ不要）。

最新リリース ↗ 初心者ガイド 機能リファレンス

書くのは、2 つのファイルだけ

インストールが済んだら、あとはこの流れ。mitiru new で作られるのは 2 つのファイルだけ ── src/ の C++（ゲームのルール）と、assets/ の HTML（画面の表示）です。

はじめてゲームを作るなら ── まずは C++ だけで作る初心者ガイド がおすすめです（HTML なし・難しい文法なし、ドッジゲームを 1 本作ります）。下は要点だけの早見表です。

ルールを C++ で書く

状態を struct にまとめ、update に毎フレームの処理を書きます。入力は in.down(...) で読み、画面に出したい値は hud.set(...) で送ります。

#include <mitiru/module/Game.hpp>
using namespace mitiru;

struct MyGame {
    float x = 600;
    int   score = 0;

    // 毎フレーム呼ばれる。入力を読んで状態を進める。
    void update(Input in, Hud hud, float dt) {
        if (in.down(Key::Right)) x += 320 * dt;   // → で右へ
        hud.set("view.hud.score", score);         // 画面へ送る
    }
    void draw(Screen& screen) {
        screen.drawRect(sgc::Rectf{x, 320, 48, 48}, sgc::Colorf{1,1,1,1});
    }
};
MITIRU_GAME(MyGame)   // これで DLL の入口が出来る

画面を HTML / CSS で書く

送った値は data-m-text で受け取って表示します。つなぎの JavaScript を書く必要はありません（画面を作るで詳しく）。

<div class="hud">SCORE <span data-m-text="view.hud.score">0</span></div>

<!-- エンジン付属の部品。これで C++ の値と画面がつながる -->
<script src="mitiru_runtime/mitiru_cef_state.js"></script>
<script src="mitiru_runtime/mitiru_bind.js"></script>

動かす

あとは mitiru run でウィンドウが開いてゲームが動きます。作り込み中は mitiru watch（保存するたび自動反映）。

mitiru run

容量と速さ（実測）

掲載しているのは 実測値です。書いたゲームは 0.2 MB の DLL ひとつになります。エンジンは header-only ── ゲーム側にコンパイルで溶け込むので、別途配る engine ライブラリはありません。成果物は、その DLL とエンジン実行環境だけです。

0.2 MBゲーム本体 (DLL)
30 MBネイティブ実行環境
305 MBHTML UI あり (CEF)
140 MBダウンロード zip
60 fps実ゲーム描画

重さは、使う機能ぶんだけ

HTML UI（CEF）を使うかどうかで、実行に要るものが切り替わります。

  • ネイティブ
    [cef] enabled = false     ゲーム本体（DLL）＋ 実行環境 ＋ DirectX のシェーダコンパイラ。Chromium は一切なし。約 30 MB。
  • HTML UI あり
    （CEF）     上に加えて、HTML / CSS を描くための CEF（Chromium） 一式（libcef.dll だけで 211 MB）。約 305 MB。
  • ダウンロード
    （zip）     上の全部 ＋ CLI ＋ サンプルを 1 つの zip に。展開してすぐ使えます。約 140 MB。
  • メモリ使用量 ネイティブ 約 180 MB、HTML UI ありで 約 360 MB。差のぶんは、まるごと Chromium です。

CEF って何？ Chromium Embedded Framework ── Web ブラウザ Chrome の中身（Chromium）を、アプリに組み込むための技術です。MitiruEngine は、メニューや HUD を 本物のブラウザエンジンで描いているから、Web の表現（CSS の影・グラデ・アニメ）がそのまま使えます。その代わり容量とメモリは「ブラウザ 1 個ぶん」かかる。だから opt-in ── HTML UI を使わなければ、まるごと外れて約 30 MB に戻ります。「Web で UI を書ける」と「軽い」を、状況で選べる、ということです。

速さ

  • 実ゲーム（ウィンドウ表示・GPU 描画）は 60fps で動きます。サンプル各種で確認済み。
  • update と描画ループは ゼロアロケーションを設計ルールに（毎フレームのメモリ確保をしない）。カクつきの原因を構造的に減らしています。
  • ヘッドレス実行（AI 自動テスト用）は CPU 描画なので別物。決定的なので、同じ入力なら結果も完全に一致します。
