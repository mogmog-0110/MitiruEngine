INSTALL

はじめかた / インストール

前提はWindows 10 / 11だけ。下の手順でmitiruコマンドが入り、自分のゲームを作りはじめられます。触るファイルはC++とHTMLの2つだけ。（Linux / Macは今後対応予定）

インストール手順

必要なものは3ステップで揃います。すでに入っている物は自動で飛ばすので、何度実行しても安全です。

  1. zipをダウンロードして展開。最新リリース からzipを落として、好きな場所に展開します。
  2. installer.exeを実行。ダブルクリックすると、C++ビルドツール（MSVC Build Tools・CMake・Windows SDK）とmitiruコマンドが入り、PATHに通ります。ツールを自分で管理したい人は、Build Toolsを手動で入れてmitiruにPATHを通すだけでも構いません。
  3. プロジェクトを作って動かす。PATHを反映させるため 新しいターミナルを開いてから実行します。
# 新規プロジェクトを作って動かす
mitiru new my-game
cd my-game
mitiru run

ウィンドウが開いてゲームのひな形が動きます。mitiru runはビルドして1回起動するコマンド。作り込み中はmitiru watchを使うと、コードを保存するたびに自動でビルドし直し、ゲームを止めずに反映されます（＝ホットリロード）。

初回ビルドだけ、5〜10分かかります。HTML UI用のCEFラッパライブラリとheader-onlyのエンジン本体を一度だけコンパイルするためです（Chromium本体はビルド済みのものをそのまま使います）。2回目以降は数秒。エディタはVisual Studio / VS Code / Vim / メモ帳、好きなもので構いません。うまくいかないときはmitiru doctorで環境を診断できます。

すぐ動くサンプルを覗きたいだけなら、展開したzipの中のMitiruEngine_Launcher.batをダブルクリックすると、一覧から選んで起動できます（コンパイラ不要）。

初心者ガイドtutorial

C++だけで赤べこの横スクロールを1本作る。難しい文法は出てきません。

機能リファレンスfeatures

描画・入力・音・物理・巻き戻し。揃っている道具の一覧。

書くのは、2つのファイルだけ

インストールが済んだら、あとはこの流れ。mitiru newで作られるのは2つのファイルだけです。src/ のC++（ゲームのルール）と、assets/ のHTML（画面の表示）です。

はじめてゲームを作るなら。C++だけで作る初心者ガイド から始めるのがおすすめ（難しい文法なし、赤べこの横スクロールを1本作る）。下は要点だけの早見表。

ルールをC++で書く

状態をstructにまとめ、updateに毎フレームの処理を書きます。入力はin.down(...)で読み、画面に出したい値はhud.set(...)で送ります。

#include <mitiru.hpp>
using namespace mitiru;

struct MyGame {
    float x = 600;
    int   score = 0;

    // 毎フレーム呼ばれる。入力を読んで状態を進める。
    void update(Input in, Hud hud, float dt) {
        if (in.down(Key::Right)) x += 320 * dt;   // → で右へ
        hud.set("view.hud.score", score);         // 画面へ送る
    }
    void draw(Screen& screen) {
        screen.drawRect({x, 320, 48, 48}, {1, 1, 1, 1});
    }
};
MITIRU_GAME(MyGame)   // これで DLL の入口が出来る

画面をHTML / CSSで書く

送った値はdata-m-textで受け取って表示します。つなぎのJavaScriptを書く必要はありません（画面を作るで詳しく）。

<div class="hud">SCORE <span data-m-text="view.hud.score">0</span></div>

<!-- エンジン付属の部品。これで C++ の値と画面がつながる -->
<script src="mitiru_runtime/mitiru_cef_state.js"></script>
<script src="mitiru_runtime/mitiru_bind.js"></script>

動かす

あとはmitiru runでウィンドウが開いてゲームが動きます。作り込み中はmitiru watch（保存するたび自動反映）。

mitiru run

容量と速さ（実測）

掲載しているのは 実測値です。書いたゲームは0.2 MBのDLLひとつになります。エンジンはheader-onlyです。ゲーム側にコンパイルで溶け込むので、別途配るengineライブラリはありません。成果物は、そのDLLとエンジン実行環境だけです。

0.2 MBゲーム本体(DLL)

書いたコードはこの1ファイルに。エンジンはheader-onlyでここに溶け込みます。

30 MBネイティブ実行環境

HTML UI（CEF）を使わない構成。Chromiumは一切なし。

305 MBHTML UIあり(CEF)

HTML / CSSを描くためのChromium一式（libcef.dllだけで211 MB）を同梱した構成。

60 fps実ゲーム描画

ウィンドウ表示・GPU描画。サンプル各種で確認済み。

重さは、使う機能ぶんだけ

HTML UI（CEF）を使うかどうかで、実行に要るものが切り替わります。

ネイティブ
[cef] enabled = false		 ゲーム本体（DLL）＋ 実行環境 ＋ DirectXのシェーダコンパイラ。Chromiumは一切なし。約30 MB。
HTML UIあり
（CEF）		 上に加えて、HTML / CSSを描くためのCEF（Chromium）一式（libcef.dllだけで211 MB）。約305 MB。
ダウンロード
（zip）		 上の全部 ＋ CLI ＋ サンプルを1つのzipに。展開してすぐ使えます。約140 MB。
メモリ使用量 ネイティブ 約180 MB、HTML UIありで 約360 MB。差のぶんは、まるごとChromiumです。

CEFって何？ Chromium Embedded Framework。WebブラウザChromeの中身（Chromium）を、アプリに組み込むための技術です。MitiruEngineは、メニューやHUDを 本物のブラウザエンジンで描いているから、Webの表現（CSSの影・グラデ・アニメ）がそのまま使えます。その代わり容量とメモリは「ブラウザ1個ぶん」かかる。だからopt-in。HTML UIを使わなければ、まるごと外れて約30 MBに戻ります。「WebでUIを書ける」と「軽い」を、状況で選べます。

速さ

  • 実ゲーム（ウィンドウ表示・GPU描画）は60fpsで動きます。サンプル各種で確認済み。
  • updateと描画ループは ゼロアロケーションを設計ルールに（毎フレームのメモリ確保をしない）。カクつきの原因を構造的に減らしています。
  • ヘッドレス実行（AI自動テスト用）はCPU描画なので別物。決定的なので、同じ入力なら結果も完全に一致します。
